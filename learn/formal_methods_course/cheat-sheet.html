Part 0 — Logic Foundations

TermMeaning

Testing vs provingTests show the presence of bugs on chosen inputs; proofs cover all inputs, relative to a spec and a model
Rice's theoremEvery non-trivial semantic property of programs is undecidable, so tools approximate, bound, or ask for annotations

Two watched literalsWatch 2 unfalsified literals per clause; visit a clause only when a watched literal becomes false

CDCLDPLL plus conflict analysis on the implication graph, clause learning, non-chronological backjumping
Decision level / implication graphDepth of decisions; DAG recording which assignments forced which
1-UIP learned clauseCut at the first unique implication point of the conflict level: learned clause is asserting after backjump

Part 2 — Verifying Programs

Hoare logic and weakest preconditions

RuleStatement
Hoare triple{P} C {Q}: if P holds before C and C terminates, Q holds after (partial correctness). Total correctness also requires termination
Assignmentwp(x := e, Q) = Q[e/x]
Sequencewp(C1; C2, Q) = wp(C1, wp(C2, Q))
Conditionalwp(if b then C1 else C2, Q) = (b ⇒ wp(C1,Q)) ∧ (¬b ⇒ wp(C2,Q))
ConsequenceFrom P ⇒ P', {P'} C {Q'}, Q' ⇒ Q conclude {P} C {Q}
While (invariant I)Init: P ⇒ I. Preserve: {I ∧ b} body {I}. Exit: I ∧ ¬b ⇒ Q
TerminationVariant (ranking function) bounded below that strictly decreases each iteration
Verification conditionFormula whose validity implies the program meets its spec; checked by an SMT solver as unsat of the negation
Strongest postconditionForward counterpart: sp(x := e, P) = ∃x0. P[x0/x] ∧ x = e[x0/x]
