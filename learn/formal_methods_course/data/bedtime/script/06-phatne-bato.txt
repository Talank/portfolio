# ६ — फाटिने बाटोको जङ्गल: Symbolic Execution, KLEE र angr

छैटौं टापुमा एउटा घना जङ्गल छ। जङ्गलभित्र एउटै बाटो छिर्छ, तर केही पाइला पछि त्यो दुई हाँगामा फाटिन्छ।

@read hush
जङ्गलमा जुनकीरी उड्छन्। तिनको हरियो उज्यालो रूखका पातमा बिस्तारै नाच्छ।

बाटोको सुरुमा एउटा ढुङ्गे खम्बा छ, र त्यसमा एउटा program कोरिएको छ। program ले एउटा number लिन्छ। number दसभन्दा ठूलो छ भने बायाँ जान्छ, नत्र दायाँ जान्छ।

[luffy]"म दुवै बाटो एकैचोटि जान्छु!"[/] लुफीले भन्यो। [luffy]"मेरो हात तन्किन्छ नि!"[/]

[robin:amused]"यस पटक लुफीको कुरा ठीक छ।"[/] रोबिनले भनिन्। [robin]"यो टापुको विधिले पनि दुवै बाटो एकैचोटि हिँड्छ।"[/]

@read teach
साधारण testing मा हामी एउटा ठोस number दिन्छौं, जस्तै पाँच। त्यसपछि program एउटै बाटो हिँड्छ। symbolic execution मा भने हामी ठोस number दिँदैनौं। हामी number को सट्टा एउटा चिन्ह दिन्छौं, जस्तै अल्फा, र त्यसलाई symbol भनिन्छ।

program ले त्यो symbol मा जोड्यो भने हामी मान गन्दैनौं, अभिव्यक्ति मात्र लेख्छौं। जस्तै, x मा एक थपियो भने x को मान अल्फा जोड एक हो भनेर लेख्छौं। हरेक variable को यस्तो अभिव्यक्ति राख्ने कापीलाई symbolic store भनिन्छ।

दोस्रो कापी पनि चाहिन्छ, र त्यसलाई path condition भनिन्छ। path condition ले यो बाटोमा आइपुग्न कुन कुन सर्त सत्य हुनुपर्छ भनेर लेख्छ। सुरुमा path condition खाली हुन्छ, र खाली भनेको सधैं सत्य हो।

अब हामी दोबाटोमा आइपुग्यौं। सर्त यो छ — अल्फा दसभन्दा ठूलो छ कि छैन?

[nami]"यहाँ बाटो फाटिन्छ, र हामी पनि फाटिन्छौं।"[/] नामीले भनिन्। [nami]"एउटा टोली बायाँ जान्छ, र उसको path condition मा अल्फा दसभन्दा ठूलो छ भनेर थपिन्छ। अर्को टोली दायाँ जान्छ, र उसको path condition मा अल्फा दसभन्दा ठूलो छैन भनेर थपिन्छ। यसलाई fork भनिन्छ।"[/]

@algo symex
symbolic execution को विधि यस्तो छ। पहिलो पाइलामा हरेक input लाई ठोस मानको सट्टा symbol बनाऊ, र symbolic store र path condition सुरु गर, जहाँ path condition सुरुमा सत्य हुन्छ। दोस्रो पाइलामा program का हरेक assignment लाई symbolic store मा अभिव्यक्तिको रूपमा लेख्दै जाऊ। तेस्रो पाइलामा सर्त c भएको हरेक branch मा fork गर, र एउटा बाटोको path condition मा c थप, अनि अर्को बाटोको path condition मा Not c थप। चौथो पाइलामा हरेक नयाँ path condition solver लाई सोध, र unsat आएको बाटो त्यहीं छाड, किनभने त्यो बाटोमा कुनै input पुग्दैन। पाँचौं पाइलामा assert वा error को ठाउँमा पुगेपछि path condition र Not assert सँगै solver लाई सोध, र sat आयो भने model नै त्यो program लाई crash गराउने ठोस input हो।
@end

[chopper]"बाटो छाड्नु भनेको के हो?"[/] चोपरले सोध्यो।

[robin:gentle]"कहिलेकाहीँ बाटो कागजमा मात्र हुन्छ।"[/] रोबिनले भनिन्। [robin]"मानौं पहिलो दोबाटोमा अल्फा दसभन्दा ठूलो छ भनेर हामी बायाँ गयौं। अगाडि अर्को दोबाटोमा अल्फा पाँचभन्दा सानो छ कि भनेर सोधिन्छ। अल्फा एकैचोटि दसभन्दा ठूलो र पाँचभन्दा सानो हुन सक्दैन। solver ले unsat भन्छ, र त्यो हाँगामा कुनै input पुग्दैन। त्यसैले हामी त्यो हाँगा हिँड्दैनौं।"[/]

@read hush
symbolic execution र Z3 को नाता यही हो। हरेक दोबाटोमा जादुगरलाई सोधिन्छ, र जादुगरले भन्छ कि यो बाटो साँचो हो कि सपना मात्र हो।

अब बाटोको अन्तिम छेउमा एउटा रातो झन्डा छ। त्यहाँ लेखिएको छ — यहाँ y कहिल्यै शून्य हुनु हुँदैन। यो assert हो।

[zoro]"त्यो सर्त तोड्ने शत्रु कहाँ लुकेको छ?"[/] जोरोले तरबारमा हात राख्दै सोध्यो।

[nami]"त्यो प्रश्न जादुगरलाई सोध।"[/] नामीले भनिन्। [nami]"यहाँसम्म आउने path condition देऊ, र y शून्य हो भनेर पनि थप। sat आयो भने model ले शत्रुको ठेगाना दिन्छ, र त्यो ठोस number हो। त्यही number लिएर program चलायौ भने crash आफ्नै आँखाले देख्छौ।"[/]

@recall symex | फाटिने बाटोको यो विधि आजको मूल पाठ हो, त्यसैले म यसलाई फेरि एकपटक बिस्तारै भन्छु।

तर यो जङ्गलमा एउटा डर पनि छ। हरेक दोबाटोमा बाटो दुई गुणा हुन्छ। दस दोबाटो पार गरेपछि हजार बाटो हुन्छन्, र बीस दोबाटो पार गरेपछि दस लाख बाटो हुन्छन्।

@read teach
यसलाई path explosion भनिन्छ, र symbolic execution को सबैभन्दा ठूलो शत्रु यही हो। loop झनै खतरनाक हुन्छ, किनभने loop को हरेक फन्को नयाँ दोबाटो हो। त्यसैले loop लाई निश्चित पटकसम्म मात्र खोलिन्छ, र त्यसलाई bound भनिन्छ।

[usopp]"मसँग एउटा उपाय छ!"[/] उसोपले भन्यो। [usopp]"पहिले एउटा साँचो number लिएर एउटै बाटो हिँड। फर्केर आउँदा कुनै एउटा दोबाटोको सर्त उल्टाऊ, र जादुगरलाई त्यो नयाँ बाटोको input माग।"[/]

[robin]"त्यो उपायको नाम पनि छ।"[/] रोबिनले भनिन्। [robin]"त्यसलाई concolic execution भनिन्छ, र त्यो concrete र symbolic को मिश्रण हो। DART र SAGE ले यही गरे, र SAGE ले ठूलो कम्पनीका program मा हजारौं bug भेट्यो।"[/]

जुनकीरीहरू अब थोरै भए। बाटोका हाँगाहरू अँध्यारोमा हराउँदै गए, तर हामीले बाटो बिराएनौं, किनभने हरेक हाँगाको सर्त हामीसँग लेखिएको छ।

@recall symex | निदाउनुअघि यो विधि अन्तिम पटक फेरि सुन, र पाँच पाइला मनमनै गन।

@tier medium

अब यस जङ्गलका दुई प्रख्यात शिकारीलाई चिनौं।

पहिलो शिकारीको नाम KLEE हो। KLEE ले C को program सिधै पढ्दैन। पहिले program लाई LLVM bitcode मा बदलिन्छ, अनि KLEE ले त्यो bitcode माथि symbolic execution चलाउँछ।

KLEE ले हरेक बाटोका लागि एउटा test पनि लेख्छ। त्यसैले काम सकिएपछि तिमीसँग धेरै बाटो छुने test को थुप्रो हुन्छ। KLEE ले पुराना UNIX औजारमा पनि वर्षौंदेखि लुकेका bug भेटेको थियो।

दोस्रो शिकारीको नाम angr हो, र यो Python मा लेखिएको हो। angr लाई source code चाहिँदैन। यसले सिधै binary पढ्छ, र त्यसैले security को काममा, जस्तै CTF खेलमा, यसको धेरै प्रयोग हुन्छ।

[franky]"source नभए पनि भित्र पस्न सकिन्छ?"[/] फ्र्याङ्कीले सोध्यो।

[nami]"सकिन्छ।"[/] नामीले भनिन्। [nami]"angr लाई पुग्नुपर्ने ठेगाना र नपुग्नुपर्ने ठेगाना भन, अनि त्यसले बीचको बाटो खोज्छ, र त्यो बाटोको input जादुगरबाट माग्छ।"[/]

@tier long

सान्जीले जङ्गलको किनारमा आगो बाल्यो, र सबै त्यसको वरिपरि बसे।

[sanji]"मलाई एउटा कुरा बुझ्न मन लाग्यो।"[/] सान्जीले भन्यो। [sanji]"यो विधिले bug भेटेन भने program ठीक छ भनेर भन्न सकिन्छ?"[/]

[robin]"सकिँदैन, र यो प्रश्न धेरै राम्रो छ।"[/] रोबिनले भनिन्। [robin]"loop लाई bound सम्म मात्र खोलियो, र केही बाटो समयले नभ्याएर छुटेका थिए। त्यसैले symbolic execution ले bug भेट्यो भने त्यो bug साँचो हुन्छ, तर bug नभेटिनु proof होइन।"[/]

यो कुरा पहिलो टापुको भाषामा भन्दा, symbolic execution ले false alarm कमै दिन्छ, तर केही bug छुटाउन सक्छ। proof चाहियो भने loop का लागि अर्कै औजार चाहिन्छ, र त्यो औजार अर्को टापुको पुरानो मन्दिरमा बस्छ।

अर्को व्यावहारिक कुरा पनि छ। साँचो program ले file पढ्छ, network छुन्छ, र system call गर्छ। symbolic execution ले ती सबैको नक्कली रूप बनाउनुपर्छ, र त्यसलाई environment model भनिन्छ।
