# १० — Lean को पहाड: Lean 4 — Types, Functions र Propositions as Types

@read hush
दसौं टापुमा एउटा अग्लो पहाड छ। पहाडको फेदमा ढुङ्गाका साना साना खुड्किला छन्, र हरेक खुड्किलामा एउटा आकार कुँदिएको छ।

पहाडको फेदमा जिम्बे पर्खिरहेका थिए। तिनी शान्त थिए, र तिनको आवाज समुद्रजस्तै गहिरो थियो।

[sage]"यो पहाडमा कसैले पनि बिना आकारको ढुङ्गा राख्न पाउँदैन।"[/] जिम्बेले भने। [sage]"हरेक ढुङ्गा आफ्नो खोपिल्टोमा ठ्याक्कै मिल्नुपर्छ। मिलेन भने पहाडको रखवालाले त्यो ढुङ्गा फर्काइदिन्छ।"[/]

@read teach
यो पहाडको नाम [..]Lean[..] हो। Lean एउटा programming language पनि हो, र एउटा proof assistant पनि हो। यहाँ हरेक कुराको एउटा type हुन्छ, र त्यो type नै ढुङ्गाको आकार हो।

[nami]"पहिले सजिलो कुराबाट सुरु गरौं।"[/] नामीले भनिन्। [nami]"पाँच भन्ने number को type Nat हो, र Nat भनेको शून्य वा त्योभन्दा ठूला पूरा number हुन्।"[/]

Lean मा function लेख्न def शब्द प्रयोग गरिन्छ। double नामको function ले एउटा Nat लिन्छ, र n जोड n फर्काउँछ। त्यसको type Nat बाट Nat जाने function हो।

तिमी hash eval लेखेर कुनै कुरा चलाउन सक्छौ। hash eval double तीन लेख्यौ भने Lean ले छ भन्छ। hash check लेख्यौ भने Lean ले त्यस कुराको type देखाउँछ।

[chopper]"यो त साधारण programming जस्तै रहेछ।"[/] चोपरले भन्यो।

[robin]"अहिलेसम्म हो।"[/] रोबिनले मुस्कुराउँदै भनिन्। [robin]"तर अब पहाडको सबैभन्दा ठूलो रहस्य आउँछ। यहाँ proposition पनि type हो, र proof पनि त्यस type को एउटा मान हो।"[/]

@read hush
एकछिन यसमा बस। दुई जोड दुई बराबर चार भन्ने वाक्य एउटा type हो। त्यो वाक्यको proof भनेको त्यो type भएको एउटा ढुङ्गा हो। ढुङ्गा भेटियो भने वाक्य सत्य हो। ढुङ्गा बनाउनै सकिँदैन भने वाक्यको proof छैन।

यो विचारलाई propositions as types भनिन्छ, र यसलाई Curry-Howard correspondence पनि भनिन्छ। यसले logic र programming लाई एउटै कुरा बनाइदिन्छ।

@algo curry-howard
Curry-Howard को तालिका यस्तो छ। पहिलो नियम यो हो कि हरेक proposition एउटा type हो, र त्यसको proof त्यो type भएको एउटा term हो। दोस्रो नियम implication को हो, र A ले B जनाउँछ भन्ने proof भनेको A को proof लिएर B को proof फर्काउने function हो। तेस्रो नियम And को हो, र A र B को proof भनेको एउटा जोडी हो, जसमा A को proof र B को proof दुवै हुन्छन्। चौथो नियम Or को हो, र A वा B को proof दुई constructor मध्ये एउटा हो, र त्यसलाई प्रयोग गर्दा cases ले दुवै अवस्था छुट्टाछुट्टै हेर्नुपर्छ। पाँचौं नियम for all को हो, र हरेक x का लागि भन्ने proof एउटा dependent function हो, जसले x लिन्छ र त्यही x को proof फर्काउँछ। छैटौं नियम exists को हो, र कुनै x छ भन्ने proof एउटा जोडी हो, जसमा witness र त्यो witness को proof हुन्छन्। सातौं नियम True र False को हो, र True को proof सजिलै बन्छ, False को कुनै proof हुँदैन, र False भेटियो भने त्यसबाट जुनसुकै कुरा प्रमाणित हुन्छ। अन्तमा theorem लेख्दा पहिले नाम, त्यसपछि colon र वाक्य, त्यसपछि colon equals र proof लेखिन्छ, र Lean को kernel ले त्यो proof को type जाँच्छ।
@end

[usopp]"त्यसो भए proof लेख्नु भनेको function लेख्नु रहेछ!"[/] उसोपले कराएर भन्यो।

[robin]"ठ्याक्कै।"[/] रोबिनले भनिन्। [robin]"A ले B जनाउँछ, र B ले C जनाउँछ भने, A ले C जनाउँछ भन्ने proof हेर। त्यो दुई function जोड्नु मात्र हो। A को proof लेऊ, पहिलो function मा हाल, र आएको नतिजा दोस्रो function मा हाल।"[/]

जिम्बेले एउटा ढुङ्गा उठाए, र त्यसलाई खोपिल्टोमा राखे। ढुङ्गा ठ्याक्कै मिल्यो, र खुड्किलामा सानो बत्ती बल्यो।

[sage]"यहाँ रखवालालाई kernel भनिन्छ।"[/] जिम्बेले भने। [sage]"kernel सानो छ, र त्यसले एउटै काम गर्छ। त्यो हरेक ढुङ्गाको आकार जाँच्छ। ठूला औजारले proof बनाउन सक्छन्, तर अन्तिम जाँच सधैं यही सानो kernel ले गर्छ।"[/]

@read teach
यसैले Lean मा भरोसा गर्न सकिन्छ। proof बनाउने औजार जति ठूलो र जटिल भए पनि, त्यसको नतिजा सानो kernel ले फेरि जाँच्छ। गल्ती भयो भने kernel ले स्वीकार्दैन।

@recall curry-howard | यो तालिका पहाडको जग हो, त्यसैले म यसलाई फेरि एकपटक भन्छु।

अब आफ्नो type बनाउने कुरा गरौं। Lean मा inductive शब्दले नयाँ type बनाइन्छ। त्यसमा कति वटा constructor छन् भनेर लेखिन्छ, र ती constructor नै त्यस type का मान बनाउने बाटा हुन्।

[nami]"Nat आफैं पनि यस्तै बनेको छ।"[/] नामीले भनिन्। [nami]"Nat का दुई constructor छन्। पहिलो zero हो। दोस्रो succ हो, र succ ले एउटा Nat लिएर त्यसको अर्को number बनाउँछ। तीन भनेको शून्यको succ को succ को succ हो।"[/]

inductive type बाट काम गर्दा pattern matching प्रयोग गरिन्छ। function ले हरेक constructor का लागि छुट्टै उत्तर दिन्छ। zero आयो भने एउटा उत्तर हुन्छ, र succ n आयो भने अर्को उत्तर हुन्छ, जसमा n को उत्तर प्रयोग गर्न पाइन्छ।

@read hush
Lean ले हरेक recursion सकिन्छ भनेर जाँच्छ। n को उत्तर n भन्दा सानो कुराबाट मात्र बनाउन पाइन्छ। यदि function अनन्त चल्न सक्थ्यो भने, त्यसले False को पनि नक्कली proof बनाउन सक्थ्यो, र पूरै पहाड ढल्थ्यो।

[zoro]"अनि सबै कुरा ढुङ्गा हो भने, ढुङ्गाको आकारको आकार के हो?"[/] जोरोले एक आँखा खोलेर सोध्यो।

[robin:amused]"राम्रो प्रश्न।"[/] रोबिनले भनिन्। [robin]"Nat को type Type हो। proposition हरूको type Prop हो। Lean मा Type माथि पनि तहहरू छन्, तर आज रात त्यति जान्नु पुग्छ।"[/]

@recall curry-howard | पहाड चढ्नुअघि यो तालिका अन्तिम पटक फेरि सुन।

जिम्बेले पहाडको माथितिर देखाए। [sage:gentle]"भोलि हामी माथि चढ्छौं।"[/] जिम्बेले भने। [sage]"त्यहाँ ढुङ्गा हातले होइन, औजारले राखिन्छ।"[/]

@tier medium

पहाडको फेदमा एउटा सानो झुपडी छ। त्यहाँ भित्तामा केही उदाहरण कुँदिएका छन्।

पहिलो उदाहरण A र B बाट B र A बनाउने proof हो। proof यस्तो छ — एउटा जोडी लेऊ, त्यसको दोस्रो भाग पहिले राख, र पहिलो भाग पछि राख। यो एउटा सानो function हो, र यो एउटा theorem पनि हो।

दोस्रो उदाहरण A वा B बाट B वा A बनाउने proof हो। यहाँ दुई अवस्था छन्। A आएको भए, त्यसलाई दायाँ constructor मा राख। B आएको भए, त्यसलाई बायाँ constructor मा राख।

@read teach
तेस्रो उदाहरण negation को हो। Lean मा not A भनेको A ले False जनाउँछ भन्ने हो। त्यसैले not A को proof भनेको A को proof लिएर False फर्काउने function हो।

[chopper]"False फर्काउने function कसरी बन्छ?"[/] चोपरले सोध्यो।

[robin]"त्यो बन्दैन, जबसम्म हातमा विरोधाभास हुँदैन।"[/] रोबिनले भनिन्। [robin]"तर हातमा A र not A दुवै छन् भने, not A लाई A दियो भने False आउँछ। त्यही False बाट तिमी जुनसुकै goal पूरा गर्न सक्छौ।"[/]

Lean मा structure पनि हुन्छ। structure भनेको धेरै field भएको एउटै constructor हो, जस्तै एउटा point मा x र y हुन्छन्। And पनि भित्रबाट यस्तै structure हो।

अर्को कुरा implicit argument हो। कुनै argument लाई curly bracket भित्र लेख्यौ भने, Lean ले त्यो आफैं अनुमान गर्छ। यसैले proof छोटो देखिन्छ।

[luffy:amused]"तिम्रो type त ब्रुक हो!"[/] लुफीले हाँस्दै भन्यो।

Lean अहिले गणितज्ञहरूको बीचमा निकै प्रख्यात छ। Mathlib भन्ने ठूलो library मा लाखौं theorem प्रमाणित भइसकेका छन्, र संसारभरका मानिसहरू त्यसमा थप्दैछन्।

@read hush
यसको अर्थ के हो भने, गणितको proof पनि अब code जस्तै review हुन्छ, र मेसिनले जाँच्छ। कसैले नयाँ proof पठायो भने, kernel ले त्यो स्वीकार्यो कि स्वीकारेन भनेर सबैले देख्न सक्छन्।

अर्को कुरा computation र proof को सम्बन्ध हो। Lean मा decide भन्ने औजार छ, र त्यसले सानो वाक्यलाई गन्ती गरेर प्रमाणित गर्छ। rfl भन्ने proof ले दुई कुरा गनेपछि उही हुन्छन् भनेर देखाउँछ।

दुई जोड दुई बराबर चार भन्ने वाक्यको proof rfl हो। Lean ले दुवै पक्ष गन्छ, र दुवैतिर चार आउँछ, त्यसैले proof पूरा हुन्छ।
