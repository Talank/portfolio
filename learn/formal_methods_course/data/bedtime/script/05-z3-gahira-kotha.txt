# ५ — जादुगरका गहिरा कोठा: Bit-Vectors, Arrays, Uninterpreted Functions र Quantifiers

पाँचौं टापु अघिल्लो बुर्जकै तल छ। ढुङ्गाको घुमाउरो सिँढी तल झर्छ, र तल चार वटा कोठा छन्।

@read hush
तल हावा चिसो छ। भित्तामा पानीका थोपा चम्किन्छन्, र टाढा कतै एउटा थोपा खसेको आवाज सुनिन्छ।

रोबिनले मैनबत्ती उठाइन् र भनिन् — [robin]"यी चार कोठा जादुगरका गहिरा ज्ञान हुन्। हरेक कोठामा एउटा theory बस्छ, र हरेक theory को आफ्नै नियम हुन्छ।"[/]

पहिलो कोठामा एउटा घडी छ, तर त्यो घडीमा बाह्र अङ्क छैनन्। त्यसमा दुई सय छपन्न वटा अङ्क छन्।

@read teach
यो bit-vector को कोठा हो। कम्प्युटरको number अनन्त हुँदैन, र त्यो निश्चित संख्याका bit मा बस्छ। आठ bit को number मा दुई सय छपन्न मान मात्र अटाउँछन्।

[franky]"अनि अन्तिम मानमा एक थपे के हुन्छ?"[/] फ्र्याङ्कीले सोध्यो।

[robin]"घडी घुमेर शून्यमा फर्किन्छ।"[/] रोबिनले भनिन्। [robin]"त्यसलाई overflow भनिन्छ। साधारण Int मा यस्तो कहिल्यै हुँदैन, तर साँचो कम्प्युटरमा सधैं हुन्छ। त्यसैले साँचो program जाँच्दा Int होइन, bit-vector चाहिन्छ।"[/]

अर्को कुरा पनि यहीं छ। उही bit को ढाँचालाई signed भनेर पढ्दा ऋणात्मक number हुन सक्छ, र unsigned भनेर पढ्दा ठूलो धनात्मक number हुन सक्छ। त्यसैले तुलना गर्दा कुन पढाइ हो भनेर भन्नैपर्छ।

दोस्रो कोठामा लामो दराज छ, र हरेक खोपामा एउटा number राखिएको छ। यो array को कोठा हो।

@read teach
array मा दुई मात्र काम हुन्छन्। Select ले कुनै खोपाबाट मान पढ्छ। Store ले कुनै खोपामा नयाँ मान राखेर नयाँ array बनाउँछ, र पुरानो array जस्ताको तस्तै रहन्छ।

तेस्रो कोठामा एउटा बन्द बाकस छ। बाकसमा एउटा प्वाल छ, र एउटा कुरा हाल्यो भने अर्को कुरा निस्किन्छ। तर बाकसभित्र के छ, कसैलाई थाहा छैन।

@read teach
यो uninterpreted function को कोठा हो। यसलाई f भनौं। f को भित्री काम थाहा छैन। एउटा मात्र नियम थाहा छ, र त्यो नियम हो — उही कुरा हाल्यो भने उही कुरा निस्किन्छ।

चौथो कोठाको ढोकामा दुई शब्द लेखिएका छन्, ForAll र Exists। यो quantifier को कोठा हो, र यो सबैभन्दा गहिरो र सबैभन्दा अँध्यारो छ।

[sage]"यी चार कोठाका नियम चार वाक्यमा भन्न सकिन्छ।"[/] जिम्बेले शान्त स्वरमा भने। [sage]"समुद्रको धारजस्तै, यी सधैं उही रहन्छन्।"[/]

@algo char-kotha
Z3 का चार theory का नियम यस्ता छन्। पहिलो नियम bit-vector को हो, र n bit को arithmetic दुईको n घातको modulo मा चल्छ, त्यसैले overflow हुँदा मान घुमेर फर्किन्छ, र signed तुलना र unsigned तुलना फरक हुन्छन्, जस्तै सानो चिन्ह signed हो र ULT unsigned हो। दोस्रो नियम array को हो, र Store गरेको array बाट Select गर्दा, उही index भए राखेकै मान आउँछ, फरक index भए पुरानो array को मान आउँछ, र दुई array का सबै खोपा बराबर भए ती array बराबर हुन्छन्। तेस्रो नियम uninterpreted function को हो, र x र y बराबर भए f x र f y पनि बराबर हुन्छन्, र f बारे यसबाहेक केही थाहा हुँदैन। चौथो नियम quantifier को हो, र ForAll वा Exists आएपछि समस्या सामान्यतया undecidable हुन्छ, त्यसैले Z3 ले pattern वा trigger हेरेर E-matching गर्छ, वा MBQI चलाउँछ, र कहिलेकाहीँ unknown भन्छ।
@end

[usopp]"तेस्रो कोठा त सबैभन्दा बेकामे लाग्यो।"[/] उसोपले भन्यो। [usopp]"भित्र के छ थाहै नभएको बाकसले के काम गर्छ?"[/]

[robin:gentle]"त्यही नै त यसको शक्ति हो।"[/] रोबिनले भनिन्। [robin]"कुनै ठूलो, गाह्रो function छ भने, त्यसलाई बन्द बाकस बनाइदेऊ। बाकस बनाएपछि पनि proof चल्यो भने, तिमीलाई त्यो function को भित्री कुरा चाहिँदैनथ्यो भन्ने प्रमाणित भयो। यसलाई abstraction भनिन्छ।"[/]

एउटा उदाहरण सुन। दुई वटा program छन्, र दुवैले उही गाह्रो function दुई पटक बोलाउँछन्, तर फरक क्रममा। ती दुई program बराबर छन् कि छैनन् भनेर जाँच्दा, function लाई f बनाइदिए पुग्छ।

@read hush
जादुगरलाई केवल यति थाहा हुन्छ कि उही input मा f ले उही output दिन्छ। प्रायः यति नै पर्याप्त हुन्छ, र गाह्रो function को गणित कहिल्यै खोल्नुपर्दैन।

@recall char-kotha | यी चार नियम आजका चार कोठा हुन्, त्यसैले म यिनलाई फेरि एकपटक बिस्तारै भन्छु।

अब पहिलो कोठामा फर्कौं, किनभने त्यहाँ एउटा प्रख्यात bug लुकेको छ।

कसैले बाइनरी सर्चमा बीचको index निकाल्न दुई छेउको जोडलाई दुईले भाग गर्छ। धेरै वर्षसम्म यो ठीक देखियो। तर दुवै छेउ ठूला भएपछि जोड overflow भयो, र index ऋणात्मक बन्यो।

[nami]"यो bug testing ले भेटेन।"[/] नामीले भनिन्। [nami]"तर दुई छेउलाई bit-vector बनाएर, जोड overflow हुन सक्छ कि सक्दैन भनेर सोधेको भए, जादुगरले तुरुन्तै sat भन्थ्यो, र model ले ठ्याक्कै ती दुई ठूला number देखाउँथ्यो।"[/]

[chopper]"अनि चौथो कोठा किन अँध्यारो छ?"[/] चोपरले डराउँदै सोध्यो।

[robin]"किनभने त्यहाँ अनन्त कुरा बस्छन्।"[/] रोबिनले भनिन्। [robin]"ForAll भन्नु भनेको हरेक x का लागि भन्नु हो। अनन्त x लाई एक एक गरेर जाँच्न सकिँदैन। त्यसैले जादुगरले चलाखी गर्छ।"[/]

@read teach
पहिलो चलाखी E-matching हो। त्यसमा ForAll भित्रको एउटा टुक्रालाई pattern भनिन्छ। त्यो pattern सँग मिल्ने कुरा सूत्रमा देखिनासाथ जादुगरले ForAll लाई त्यही कुरामा उतार्छ। दोस्रो चलाखी MBQI हो, र त्यसमा जादुगरले एउटा model बनाउँछ, अनि त्यो model ले ForAll तोड्छ कि तोड्दैन भनेर जाँच्छ।

@recall char-kotha | मैनबत्ती छोटो हुँदैछ, त्यसैले यी चार नियम अन्तिम पटक फेरि सुन।

@tier medium

अब केही मसिना कुरा सुनौं, किनभने interview मा यस्तै प्रश्न आउँछन्।

bit-vector मा भाग पनि अनौठो हुन्छ। signed भाग र unsigned भाग फरक हुन्छन्। दायाँ सार्ने कामको पनि दुई किसिम छन् — एउटाले चिन्हको bit जोगाउँछ, र अर्कोले बायाँबाट शून्य भर्छ।

[franky]"यो त सुपर लाग्यो! यो त मेरो इन्जिनको गियर जस्तै रहेछ।"[/] फ्र्याङ्कीले भन्यो। [franky]"गियरको दाँत गनिएका हुन्छन्, र अन्तिम दाँतपछि पहिलो दाँत फेरि आउँछ।"[/]

Z3 ले bit-vector लाई भित्रभित्रै bit bit गरेर SAT को सूत्रमा बदल्छ। यसलाई bit-blasting भनिन्छ। त्यसैले गुणा र भाग धेरै भएको सूत्र सुस्त हुन सक्छ।

array को कोठामा पनि एउटा मसिनो कुरा छ। Z3 को array को आकार हुँदैन, र त्यसको index जुनसुकै किसिमको हुन सक्छ। साँचो program को memory लाई पनि ठूलो array भनेर देखाउन सकिन्छ, जहाँ index ठेगाना हो र मान byte हो।

uninterpreted function को नियमलाई congruence भनिन्छ। Z3 भित्र यसलाई congruence closure नामको छिटो विधिले सम्हालिन्छ, र त्यसले बराबर कुराहरूको समूह बनाउँदै जान्छ।

@tier long

ब्रुक चौथो कोठाको ढोकामा उभियो, र अँध्यारोतिर हेर्‍यो।

[brook]"मेरो आफ्नै छाया पनि यहाँ देखिँदैन।"[/] ब्रुकले भन्यो। [brook]"तर म डराउँदिनँ, किनभने म त कङ्काल नै हुँ।"[/]

quantifier भएको सूत्र लेख्दा एउटा सल्लाह याद राख। सकेसम्म ForAll नलेख। लेख्नैपर्‍यो भने आफैं pattern देऊ, ताकि जादुगरले कुन बेला उतार्ने भनेर बुझोस्।

नराम्रो pattern दियौ भने जादुगरले ForAll लाई अनन्त पटक उतार्न सक्छ। त्यसलाई matching loop भनिन्छ, र त्यसबेला जादुगर कहिल्यै रोकिँदैन।

[sage]"समुद्रमा पनि यस्तै हुन्छ।"[/] जिम्बेले भने। [sage]"एउटा भुमरीमा पसेपछि डुङ्गा घुमिरहन्छ। बाहिर निस्कने बाटो पहिल्यै सोच्नुपर्छ।"[/]

यसैले Dafny जस्ता औजारले trigger छान्न सावधानी अपनाउँछन्। ती औजार पछिका टापुमा आउँछन्।
