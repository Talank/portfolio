# ३ — कप्तानको हुकुम: Tool Use र Agent Loop

तेस्रो टापुमा एउटा अग्लो चट्टान छ। चट्टानको टुप्पोबाट सिङ्गो टापु देखिन्छ। तल जङ्गल छ, खोला छ, र एउटा सानो गाउँ छ।

लुफी चट्टानको टुप्पोमा बस्यो। उसले सबै देख्थ्यो, तर त्यहाँबाट केही छुन सक्दैनथ्यो। उसको काम सोच्नु र हुकुम दिनु थियो।

@read teach
यो चट्टानको कप्तान नै model हो। model ले शब्द मात्र लेख्छ। उसले आफैं फाइल खोल्दैन, मौसम हेर्दैन, र हिसाब चलाउँदैन। तर उसले भन्न सक्छ कि मलाई यो tool यो input सहित चलाइदेऊ। त्यसलाई tool use भनिन्छ।

तल टोली तयार थियो। नामी नक्सा पढ्ने tool थिइन्। सान्जी भान्सा चलाउने tool थियो। उसोप टाढा हेर्ने tool थियो। हरेकको नाम थियो, कामको वर्णन थियो, र के के input चाहिन्छ भन्ने सूची थियो।

[nami]"model लाई tool चिनाउने तरिका यही हो।"[/] नामीले भनिन्। [nami]"हरेक tool को name, description र input_schema हुन्छ। description राम्रोसँग लेख, किनभने model ले त्यही पढेर कुन tool कहिले चलाउने भनेर छान्छ।"[/]

लुफीले माथिबाट चिच्यायो — [luffy]"उसोप, उत्तरतिर हेर! त्यहाँ के छ?"[/]

@read teach
यो हुकुम API मा एउटा tool_use block बनेर आउँछ। त्यसमा tool को name हुन्छ, input हुन्छ, र एउटा id हुन्छ। जवाफको stop_reason चाहिँ tool_use हुन्छ। यसको अर्थ हो कि model रोकिएको छ, र नतिजा पर्खिरहेको छ।

उसोपले दूरबीन उठायो, र उत्तरतिर हेर्यो। [usopp]"उत्तरमा एउटा पुल छ, तर त्यो भाँचिएको छ।"[/] उसले भन्यो।

@read teach
अब त्यो नतिजा फिर्ता लैजानुपर्छ। तिम्रो code ले tool चलाउँछ, र नतिजालाई tool_result block मा राख्छ। tool_result मा उही tool_use_id लेखिन्छ, ताकि model ले कुन हुकुमको नतिजा हो भनेर चिनोस्। त्यो tool_result एउटा user message भित्र पठाइन्छ।

@algo agent-loop
agent loop को विधि यस्तो छ। पहिलो चरणमा हरेक tool को name, description र input_schema लेख। दोस्रो चरणमा messages र tools सँगै model लाई पठाऊ। तेस्रो चरणमा stop_reason हेर, र tool_use छ भने model को पूरा जवाफ assistant message को रूपमा messages मा थप। चौथो चरणमा हरेक tool_use block बाट name र input निकाल, र त्यो function आफ्नै code मा चलाऊ। पाँचौं चरणमा हरेक नतिजालाई tool_result block मा राख, त्यसमा उही tool_use_id लेख, र ती सबै एउटै user message मा थप। tool असफल भयो भने error लाई is_error सहित tool_result मै पठाऊ। छैटौं चरणमा फेरि model लाई पठाऊ, र यो क्रम दोहोर्याइरह। stop_reason end_turn आयो भने वा max turns पुग्यो भने loop रोक।
@end

लुफीले पुलको खबर सुन्यो, र फेरि सोच्यो। [luffy]"नामी, अर्को बाटो छ कि छैन, नक्सा हेर!"[/] उसले चिच्यायो।

@read hush
यही नै loop हो। कप्तानले हुकुम दिन्छ, टोलीले काम गर्छ, नतिजा कप्तानकहाँ फर्कन्छ, र कप्तान फेरि सोच्छ। हरेक चक्रमा model ले नयाँ जानकारी पाउँछ, र अर्को पाइला छान्छ।

[zoro]"यो loop कहिले सकिन्छ?"[/] जोरोले सोध्यो।

[nami]"दुई तरिकाले सकिन्छ।"[/] नामीले भनिन्। [nami]"model ले आफैं भन्छ कि काम सकियो, र त्यसबेला stop_reason end_turn हुन्छ। अथवा हामीले राखेको max turns को सीमा पुग्छ। त्यो सीमा कहिल्यै नबिर्स, नत्र कप्तानले रातभरि हुकुम दिइरहन्छ, र पैसा पनि सकिन्छ।"[/]

@recall agent-loop | कप्तानको loop फेरि एकपटक, बिस्तारै सुन।

रोबिनले एउटा सानो कुरा सम्झाइन्। [robin]"एउटै जवाफमा धेरै tool_use block आउन सक्छन्।"[/] उनले भनिन्। [robin]"कप्तानले एकै पटक उसोप र नामी दुवैलाई हुकुम दिन सक्छ। ती दुवै काम सँगै चलाऊ, र दुवैका tool_result एउटै user message मा फिर्ता पठाऊ। कुनै tool_use लाई जवाफ नदिई छाड्यौ भने API ले error दिन्छ।"[/]

@read teach
tool असफल हुँदा पनि loop तोड्नु हुँदैन। error लाई tool_result मा राख, is_error true बनाऊ, र model लाई देखाऊ। model ले प्रायः आफ्नो input सुधार्छ, वा अर्को बाटो छान्छ। जसरी लुफीले भाँचिएको पुल सुनेर अर्को बाटो खोज्यो, त्यसरी नै model ले error पढेर अर्को पाइला चाल्छ।

नामीले नक्सा हेरिन्, र दक्षिणतिर एउटा सानो डुङ्गाघाट भेटिन्। लुफीले अन्तिम पटक सोच्यो, अनि भन्यो कि टोली डुङ्गाबाट जानेछ। अब कुनै हुकुम बाँकी थिएन, र उसले शान्तसँग आँखा चिम्ल्यो।

@recall agent-loop | चट्टान छाड्नुअघि loop अन्तिम पटक सुन।

@tier medium

सान्जीले भान्साबाट एउटा प्रश्न सोध्यो — [sanji]"model लाई tool चलाउन बाध्य पार्न सकिन्छ?"[/]

[nami]"सकिन्छ।"[/] नामीले भनिन्। [nami]"tool_choice भन्ने setting छ। auto राख्यौ भने model आफैं छान्छ। any राख्यौ भने कुनै न कुनै tool चलाउनैपर्छ। एउटा tool को नाम दियौ भने त्यही tool चलाउनैपर्छ। none राख्यौ भने tool चलाउँदैन।"[/]

@read teach
loop लेख्दा तीन वटा सानो कुरा ध्यानमा राख। पहिलो, tool को नतिजा धेरै लामो भयो भने काटेर पठाऊ, नत्र context window भरिन्छ। दोस्रो, हरेक turn को token र समय log गर, किनभने पछि evaluation गर्दा यही trace चाहिन्छ। तेस्रो, फाइल मेटाउने वा पैसा पठाउने जस्ता खतरनाक tool मा मानिसको स्वीकृति माग।

@tier long

रोबिनले अन्तर्वार्ताको कुरा सम्झिन्। [robin]"framework बिना agent loop लेख भनेर सोधिन्छ।"[/] उनले भनिन्। [robin]"त्यसको उत्तर एउटा while loop मात्र हो। भित्र API call छ, stop_reason को जाँच छ, tool चलाउने भाग छ, र tool_result थप्ने भाग छ। बाहिर max turns को गन्ती छ। यति लेख्न सक्यौ भने framework भित्र के हुन्छ भनेर पनि बुझ्छौ।"[/]

[chopper]"tool को description कस्तो लेख्ने?"[/] चोपरले सोध्यो।

[robin]"नयाँ सहकर्मीलाई सिकाएजस्तै लेख।"[/] रोबिनले भनिन्। [robin]"tool ले के गर्छ, कहिले चलाउने, कहिले नचलाउने, र नतिजा कस्तो आउँछ भनेर लेख। tool को नाम र input पनि स्पष्ट राख। धेरै मिल्दाजुल्दा tool राख्यौ भने model अलमलिन्छ।"[/]

@read hush
चट्टानमा हावा चल्यो, र तल खोलाको आवाज मधुरो भयो। लुफी अझै टुप्पोमै सुतिरहेको छ।
