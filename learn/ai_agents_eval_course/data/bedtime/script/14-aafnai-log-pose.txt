# १४ — आफ्नै लग पोज: Capstone, Agent र Eval Harness, र Interview Playbook

चौधौं टापु अन्तिम टापु हो। यहाँ कुनै शत्रु छैन, कुनै भुलभुलैया छैन। यहाँ एउटा खाली कार्यशाला मात्र छ, र भित्तामा अघिल्ला सबै टापुका नक्सा टाँसिएका छन्।

[nami]"यहाँ हामी आफ्नै लग पोज बनाउँछौं।"[/] नामीले भनिन्। [nami]"लग पोजले दिशा देखाउँछ। हाम्रो लग पोजले चाहिँ हाम्रो agent ठीक दिशामा गइरहेको छ कि छैन भनेर देखाउँछ। त्यसलाई eval harness भनिन्छ।"[/]

@read teach
पहिले agent बनाइन्छ। त्यसमा तेस्रो टापुको agent loop हुन्छ, केही tool हुन्छन्, र एउटा स्पष्ट system prompt हुन्छ। आवश्यक परे पाँचौं टापुको RAG ले खोज्ने tool दिइन्छ। तर agent जति राम्रो बनाए पनि, harness बिना त्यो राम्रो भयो भनेर कसैले थाहा पाउँदैन।

फ्र्याङ्कीले टेबलमा छ वटा काठका बाकस राख्यो। [franky]"harness छ भागको मेसिन हो!"[/] उसले भन्यो। [franky]"हरेक बाकस एउटा भाग हो, र सबै क्रमैसँग जोडिन्छन्।"[/]

@algo harness
eval harness बनाउने विधि यस्तो छ। पहिलो चरणमा dataset loader लेख, जसले हरेक काम id, input र जाँच्ने तरिका सहित पढ्छ। दोस्रो चरणमा runner लेख, जसले हरेक कामलाई sandbox भित्र agent loop मा चलाउँछ, max turns राख्छ, र semaphore, retry र cache प्रयोग गर्छ। तेस्रो चरणमा हरेक run को पूरा trace JSONL मा लेख। चौथो चरणमा grader लेख, जसले सम्भव भए test वा exact match ले अङ्क दिन्छ, र नभए मानिससँग जाँचिएको LLM judge ले अङ्क दिन्छ। पाँचौं चरणमा aggregator लेख, जसले success rate, खर्च र latency निकाल्छ, र bootstrap ले confidence interval दिन्छ। छैटौं चरणमा report लेख, जसले baseline सँग paired तुलना देखाउँछ, र सबैभन्दा नराम्रा असफल उदाहरण पढ्न दिन्छ।
@end

[usopp]"यसमा त सबै टापु भेटिए।"[/] उसोपले आश्चर्यले भन्यो।

[robin]"हो।"[/] रोबिनले भनिन्। [robin]"runner भित्र तेस्रो टापुको loop छ, र बाह्रौं टापुको semaphore र cache छ। grader भित्र आठौं र दसौं टापु छन्। aggregator भित्र एघारौं टापु छ। trace भित्र तेह्रौं टापु छ। harness भनेको यात्राको सम्पूर्ण नक्सा एउटै मेसिनमा राख्नु हो।"[/]

@read teach
harness लाई पनि जाँच। पहिले सधैं सही उत्तर दिने नक्कली agent चलाऊ, र अङ्क सय प्रतिशत आउँछ कि आउँदैन हेर। अनि सधैं गलत उत्तर दिने नक्कली agent चलाऊ, र अङ्क शून्य आउँछ कि आउँदैन हेर। यी दुई जाँच पास नभई वास्तविक agent को अङ्कमा विश्वास नगर।

@recall harness | लग पोज बनाउने विधि फेरि एकपटक सुन।

अब नामीले भित्तामा एउटा नयाँ कागज टाँसिन्। त्यसको शीर्षक अन्तर्वार्ताको नक्सा थियो।

[nami]"अन्तर्वार्तामा कसैले भन्छ कि यो कामका लागि agent बनाऊ।"[/] नामीले भनिन्। [nami]"सिधै code लेख्न सुरु नगर। पहिले प्रश्न सोध। काम ठ्याक्कै के हो? सफलता कसरी नापिन्छ? कति खर्च र कति समय स्वीकार्य छ? कुन काम खतरनाक हुन्छ?"[/]

@read teach
त्यसपछि सबैभन्दा सरल baseline भन। एउटा राम्रो prompt ले काम चल्छ कि चल्दैन भनेर पहिले नाप्ने कुरा भन। अनि सानो eval set बनाउने योजना भन, जसमा बीसदेखि पचास वटा वास्तविक काम हुन्छन्। त्यसपछि मात्र workflow वा agent तिर जाऊ, र हरेक थपिएको जटिलताले अङ्क बढायो कि बढाएन भनेर interval सहित नाप।

[zoro]"अनि अङ्क आएपछि?"[/] जोरोले सोध्यो।

[nami]"अङ्क आएपछि गल्ती पढ।"[/] नामीले भनिन्। [nami]"असफल trace पढेर गल्तीलाई समूहमा बाँड। सबैभन्दा ठूलो समूह पहिले सुधार गर। अनि फेरि harness चलाऊ। यो चक्र नै काम हो, र अन्तर्वार्तामा यही चक्र स्पष्ट भन्न सक्यौ भने तिमी तयार छौ।"[/]

@read hush
सोध, baseline बनाऊ, नाप, गल्ती पढ, सुधार गर, र फेरि नाप। यो चक्र सम्झ, किनभने यो हरेक टापुमा लागू हुन्छ।

फ्र्याङ्कीले अन्तिम बाकस जोड्यो। मेसिन बिस्तारै घुम्न थाल्यो, र त्यसको सियोले एउटा दिशा देखायो। टोलीले त्यो सियो हेर्यो, र सबै चुपचाप मुस्कुराए।

@recall harness | कार्यशाला छाड्नुअघि harness को विधि अन्तिम पटक सुन।

@tier medium

रोबिनले अन्तर्वार्ताका केही सामान्य प्रश्न सम्झाइन्। [robin]"तिम्रो agent को अङ्क बढ्यो भनेर कसरी थाहा पायौ भनेर सोधिन्छ।"[/] उनले भनिन्। [robin]"उत्तरमा उही प्रश्नमा paired तुलना गरेको, bootstrap interval ले शून्यलाई नछोएको, र test set लाई अन्त्यमा मात्र छोएको कुरा भन। अनि contamination को सम्भावना पनि जाँचेको कुरा भन।"[/]

@read teach
अर्को सामान्य प्रश्न judge को हो। तिम्रो LLM judge भरपर्दो छ भनेर कसरी भन्छौ भनेर सोधिन्छ। उत्तरमा मानिसले label गरेको सेटसँग Cohen's kappa नापेको, position bias हटाउन क्रम साटेर दुवै पटक चलाएको, र फरक परिवारको judge प्रयोग गरेको कुरा भन।

@tier long

[chopper]"अनि agent production मा गएपछि?"[/] चोपरले सोध्यो।

[robin]"त्यसपछि पनि नाप्ने काम रोकिँदैन।"[/] रोबिनले भनिन्। [robin]"production को trace बाट नमुना लेऊ, र तिनलाई judge र मानिसले जाँचून्। नयाँ गल्ती भेटियो भने regression suite मा थप। model को नयाँ version आयो भने पहिले harness चलाऊ, अनि मात्र बदल। लग पोज सधैं हातमा राख।"[/]

[luffy]"मलाई त खजाना मात्र चाहिन्छ।"[/] लुफीले हाँस्दै भन्यो।

[nami]"खजाना भेटेको हो कि होइन भनेर पनि त नाप्नुपर्छ।"[/] नामीले उसको टोपी मिलाइन्। सबै हाँसे।

@read hush
कार्यशालाको बत्ती मधुरो भयो। नयाँ लग पोज टेबलमा शान्तसँग घुमिरहेको छ, र त्यसको सियो अँध्यारोमा पनि सही दिशा देखाइरहेको छ।
