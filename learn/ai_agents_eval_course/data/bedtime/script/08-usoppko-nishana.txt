# ८ — उसोपको निशाना: Evaluation Fundamentals, Golden Dataset र pass@k

आठौं टापुमा एउटा चौडा मैदान छ। मैदानको अर्को छेउमा सयौं निशाना गाडिएका छन्। हरेक निशानाको बीचमा एउटा सानो रातो घेरा छ।

यो टापु जाँचको टापु हो। अब हामी agent बनाउने होइन, नाप्ने यात्रामा छौं।

उसोपले आफ्नो गुलेली निकाल्यो, र छाती फुलायो। [usopp]"म संसारकै सबैभन्दा राम्रो निशानेबाज हुँ!"[/] उसले भन्यो।

[nami]"त्यो कसरी थाहा हुन्छ?"[/] नामीले सोधिन्। [nami]"दाबी गर्न सजिलो छ। नापेर देखाऊ।"[/]

@read teach
evaluation को जग यहीँ छ। पहिले सफलता के हो भनेर परिभाषा गर। त्यसपछि प्रश्नहरूको एउटा स्थिर सेट बनाऊ, जसलाई golden dataset भनिन्छ। हरेक प्रश्नसँग सही उत्तर वा जाँच्ने तरिका हुन्छ। अनि system लाई त्यही सेटमा चलाऊ, र हरेक पटक उही metric ले नाप।

रोबिनले मैदानलाई तीन भागमा बाँडिन्। [robin]"यो पहिलो भाग अभ्यासको हो, र यहाँ जति पनि हेर्न पाइन्छ।"[/] उनले भनिन्। [robin]"दोस्रो भाग dev set हो, र यहाँ prompt र setting सुधार्दा नाप्छौ। तेस्रो भाग test set हो। त्यसलाई अन्त्यमा मात्र एकपटक छुन्छौ। test set हेरेर prompt सुधार्यौ भने त्यो अङ्कले झूट बोल्छ।"[/]

@read teach
metric काम अनुसार छानिन्छ। छोटो उत्तर भएका प्रश्नमा exact match चल्छ। शब्दहरू आंशिक मिल्ने काममा F1 चल्छ। code मा सबैभन्दा भरपर्दो metric functional correctness हो, जसमा code चलाइन्छ र unit test पास भयो कि भएन हेरिन्छ। code को अक्षर मिल्यो कि मिलेन भनेर हेर्नुभन्दा code ले सही काम गर्यो कि गरेन भनेर हेर्नु धेरै राम्रो हुन्छ।

उसोपले एउटा निशानामा एक पटक मात्र हान्यो। गोली रातो घेरामा लाग्यो। तर अर्को निशानामा पाँच पटक हान्दा एउटा मात्र घेरामा लाग्यो।

[chopper]"उसोपलाई कति अङ्क दिने?"[/] चोपरले सोध्यो।

@read teach
यसका लागि pass@k छ। pass@k भनेको k वटा प्रयासमध्ये कम्तीमा एउटा सही हुने सम्भावना हो। pass@1 भनेको पहिलो प्रयासमै सही हुने सम्भावना हो। तर k वटा मात्र नमुना बनाएर सिधै गन्यौ भने अङ्क धेरै हल्लिन्छ। त्यसैले धेरै नमुना बनाएर एउटा unbiased सूत्र प्रयोग गरिन्छ।

@algo passk
unbiased pass@k को विधि यस्तो छ। पहिलो चरणमा हरेक problem का लागि n वटा नमुना बनाऊ, जहाँ n कम्तीमा k जति हुन्छ। दोस्रो चरणमा हरेक नमुनालाई unit test ले जाँच, र सही नमुना गनेर त्यो सङ्ख्यालाई c भन। तेस्रो चरणमा n घटाउ c को मान k भन्दा सानो छ भने त्यो problem को pass@k एक हुन्छ। नत्र pass@k बराबर एक घटाउ एउटा भिन्न हुन्छ, जसको अंश n घटाउ c बाट k छान्ने तरिकाको सङ्ख्या हो, र हर n बाट k छान्ने तरिकाको सङ्ख्या हो। चौथो चरणमा यो अङ्क सबै problem मा निकाल, र तिनको औसत लेऊ।
@end

[nami]"त्यो भिन्नको अर्थ सजिलो छ।"[/] नामीले भनिन्। [nami]"n वटा नमुनाबाट k वटा छानेर हेर। ती सबै k गलत हुने सम्भावना त्यो भिन्न हो, किनभने गलत नमुना n घटाउ c वटा मात्र छन्। एकबाट त्यो घटायौ भने कम्तीमा एउटा सही हुने सम्भावना आउँछ।"[/]

@read hush
सबै k गलत हुने सम्भावना निकाल। अनि त्यसलाई एकबाट घटाऊ। pass@k को सारा रहस्य यत्ति हो।

@recall passk | निशानाको विधि फेरि एकपटक सुन।

उसोपले दुई सय पटक हान्यो, र रोबिनले हरेक निशानाको रातो घेरा गनिन्। अनि नामीले सूत्रले अङ्क निकालिन्। उसोपको pass@1 चालीस प्रतिशत आयो, र pass@10 नब्बे प्रतिशत आयो।

[usopp]"त्यसो भए म नब्बे प्रतिशतको निशानेबाज हुँ!"[/] उसोप खुसीले उफ्रियो।

[robin]"दस पटक हान्न पाउँदा मात्र।"[/] रोबिनले मुस्कुराएर भनिन्। [robin]"pass@k रिपोर्ट गर्दा k कति हो, n कति हो, र temperature कति हो, सबै लेख। नत्र दुई अङ्क तुलना गर्न मिल्दैन। प्रयोगकर्ताले एक पटक मात्र उत्तर देख्छ भने pass@1 नै असली अङ्क हो।"[/]

@read teach
pass@k को अर्को प्रयोग पनि छ। धेरै नमुनामध्ये एउटा छान्ने verifier वा test छ भने pass@k ले त्यो system को माथिल्लो सीमा देखाउँछ। verifier छैन भने k ठूलो भएर मात्र प्रयोगकर्तालाई फाइदा हुँदैन।

@recall passk | मैदान छाड्नुअघि pass@k को विधि अन्तिम पटक सुन।

@tier medium

रोबिनले golden dataset बनाउने तरिका सुनाइन्। [robin]"पहिले वास्तविक प्रयोगकर्ताका प्रश्न जम्मा गर।"[/] उनले भनिन्। [robin]"त्यसमा सजिला, कठिन र किनाराका प्रश्न मिसाऊ। हरेक उत्तर विशेषज्ञले जाँच। अनि production मा देखिएका हरेक नयाँ गल्तीलाई dataset मा थप। यसरी dataset जीवित रहन्छ।"[/]

@read teach
अङ्क मात्र नहेर, गल्ती पनि पढ। पचास वटा असफल नमुना हातैले पढेर तिनलाई समूहमा बाँड। कुनमा format बिग्रियो, कुनमा गलत tool छानियो, कुनमा तथ्य गलत भयो भनेर गन। यसलाई error analysis भनिन्छ, र अर्को सुधार कहाँ गर्ने भनेर यसले नै बताउँछ।
