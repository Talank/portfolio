Part 0 — LLM Building Blocks

LLM APIs: messages, tokens, sampling, context, cost

API / conceptWhat to remember
client.messages.create(model=, max_tokens=, system=, messages=)Stateless: send the whole conversation each turn. Default model claude-opus-5-5.
resp.contentA list of blocks (text, thinking, tool_use). Iterate and check block.type; never assume content[0].text.
resp.stop_reasonend_turn, max_tokens (truncated), tool_use, pause_turn, refusal. Check it before parsing.
resp.usageinput / output / cache-read / cache-write tokens: the only correct basis for cost.
client.messages.count_tokens(...)Count tokens with the target model; never tiktoken or chars/4.
SamplingTemperature rescales logits, top-p keeps the smallest set with mass p. Newest Claude models reject temperature/top_p/top_k; temperature 0 is not bit-deterministic anyway.
thinking={"type": "adaptive"}, output_config={"effort": ...}Current thinking control; effort low to max trades depth for tokens. budget_tokens is rejected on the newest models.
Context windowOne budget for input + output; agent loops grow it every turn (cost grows roughly quadratically with turns).
cache_control={"type": "ephemeral"}Prompt caching is a prefix match: stable content first, volatile content after the breakpoint; verify with usage.cache_read_input_tokens.
client.messages.stream(...) + .get_final_message()Streaming cuts time to first token, not total time; required for very large max_tokens.

Prompting and structured output

TechniqueWhat to remember
Prompt as interface specRole and rules, delimited context (XML-style tags), examples, explicit output contract. Version and evaluate prompts like code.
Few-shotBalance labels and vary surface form; known biases: majority label, recency, order sensitivity.
client.messages.parse(..., output_format=PydanticModel)Schema-validated result in resp.parsed_output.
output_config={"format": {"type": "json_schema", "schema": ...}}Constrained decoding with a raw schema (the old output_format parameter on create is deprecated).
Strict tools: "strict": trueTool input guaranteed to match the schema (needs additionalProperties: false + required).
Validate + retry with errorsSchema-valid is not correct: semantic validators, feed exact errors back, cap retries.
Removed on current modelsAssistant prefill and forced tool_choice (any/tool) return 400; use structured outputs or prompt instructions.

Tool use: the agent loop

RuleWhy
Tool = name, description, input_schemaThe description is a prompt: say when to use it, what it returns, how it fails.
Append resp.content unchanged as the assistant turnKeeps tool_use ids and thinking blocks; text-only appends cause 400s.
All tool_result blocks in ONE user message, matched by tool_use_idRequired pairing; splitting also discourages parallel tool calls.
is_error: true resultsLet the model recover from tool failures; stop the loop only on unrecoverable ones.
BudgetsMax turns, token / cost budget, repeat detection, explicit handling of every stop_reason.
client.beta.messages.tool_runner(...) + @beta_toolSDK-run loop for your own tools; hand-write the loop only when you need full control.

Part 2 — Evaluation Fundamentals

Eval fundamentals

Concept / formulaWhat to remember
Task definitionInput distribution, output contract, scoring function, aggregation rule.
SplitsIterate on dev, report on a held-out test you never read failures from; split by group (document, repo); random, stratified by tag.
Golden setid, source, tags, reference, notes, date; hash the JSONL and store the hash with results.
Harness self-testOracle must score ~100%, null baseline (empty / constant) must fail.
Exact matchNormalize (lowercase, strip punctuation, drop a/an/the, collapse spaces), max over references.
Token F1Counter(pred) & Counter(gold); P = shared/len(pred), R = shared/len(gold).
BLEUBP · exp(∑ ¼ log pn), clipped n-gram precision, BP = exp(1 - r/c) if c ≤ r. Poor for code; use sacrebleu.
Execution-basedRun tests in a fresh, isolated process with a timeout; only as good as the tests.
pass@k (unbiased)1 - C(n-c, k)/C(n, k), n ≥ k; compute as 1 - ∏i=n-c+1..n(1 - k/i). Plug-in 1-(1-c/n)k is biased low.
pass^kC(c, k)/C(n, k): all k trials succeed (reliability).

LLM-as-a-judge and human evaluation

Concept / formulaWhat to remember
Pointwise / pairwise / reference-guidedPointwise for tracking, pairwise for A/B, reference-guided whenever references exist.
RubricAtomic binary criteria, reasoning before verdict, structured output, candidates as untrusted data, "length is not a criterion".
Position biasJudge both orders; keep verdicts that survive the swap; report position-consistency rate.
Verbosity / self-preferenceAtomic criteria and length checks / a judge from a different family, or a jury.
Calibration50-200 human-labeled items; human-human agreement is the ceiling; per-criterion kappa, recall on "fail".
Cohen's kappa(po - pe)/(1 - pe), pe = ∑k p1kp2k; weighted kappa for ordinal labels; beware skewed prevalence.
Fleiss' kappa / Krippendorff's alpham raters per item / any raters, missing data, nominal-ordinal-interval: α = 1 - Do/De.
Bradley-TerryP(i beats j) = si/(si + sj); arena leaderboards fit it to pairwise votes.
Judge hygienePin the judge model, assert the served model, no silent fallbacks, version the rubric.

Statistics for evals

Tool / formulaWhat to remember
SE of accuracy√(p(1-p)/n); 95% half-width ~1/√n at p = 0.5 (100 items: ±10 pts, 500: ±4.4, 1,068: ±3).
Wilson interval(p + z²/2n ± z√(p(1-p)/n + z²/4n²)) / (1 + z²/n); use for small n or p near 0/1.
BootstrapResample the independent unit (items, or clusters) with replacement, B = 1k-10k, percentile CI.
Paired bootstrapResample item indices; CI on mean(a - b). Pairing removes item-difficulty variance.
Sign-flip permutation testFlip each per-item difference's sign at random; p = (hits + 1)/(B + 1).
McNemar (exact)Only discordant items: two-sided binomial test of n10 of n10 + n01. 28 vs 9 gives p = 0.0026.
Clustered SESum residuals per cluster: Var = G/(G-1) · ∑g(∑i∈g ri)²/n². Cluster by repo, passage, or item when using reps.
Sample sizeOne accuracy: n = z²p(1-p)/m². Paired: n ≈ (zα/2√pd + zβ√(pd - δ²))²/δ² (pd = 0.2, δ = 0.05: ~626).
Variance decompositionVar(mean) ≈ σb²/n + σw²/(nR): reps shrink only the within-item term.
Flaky eval itemsRerun R times: always-pass / always-fail / flaky. Keep flaky items (they measure p); fix harness causes (shared state, timeouts).
ReportingEffect + CI + design (n x R) + dataset version; correct for many comparisons (Holm) or confirm on held-out.

Evaluating agents

ConceptWhat to remember
Outcome vs trajectoryPrimary: end state in the environment. Trajectory as constraints (forbidden calls, ordering, budgets), not a golden path.
Success definitionoutcome AND no safety violation AND within step / cost / latency budget.
Tool metricsRecall (expected calls made), precision (calls that were expected), argument accuracy, tool error rate, repeated calls.

SafetyFail-on-any aggregation; prompt-injection suites through every untrusted channel; red-team finds become regression cases; measure over-refusal too.
Reliabilitypass^k = C(c,k)/C(n,k); 2 of 4 successes gives pass^1 0.50, pass^2 0.17.
