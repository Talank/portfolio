Part 0 — The Compiler Pipeline

The phases

PhaseInput → outputWhat it catches / does
Lexing (scanning)characters → tokensRegular languages / DFAs; maximal munch; drops whitespace and comments; bad characters
Parsingtokens → parse tree / ASTContext-free grammar; syntax errors; the AST drops punctuation the tree no longer needs
Semantic analysisAST → annotated AST + symbol tablesName resolution, scoping, type checking, overload resolution
Lowering / IR genAST → IR (TAC, CFG, SSA)Turns nested expressions and structured control flow into simple instructions and jumps
OptimizationIR → IRConstant folding/propagation, DCE, CSE, LICM, inlining. Each pass rests on a dataflow fact
Code generationIR → machine code / bytecodeInstruction selection, register allocation (graph coloring / linear scan), scheduling
Front / middle / back endlanguage-specific / IR / target-specificThe reason LLVM works: N languages + M targets need N+M components, not N×M

Lexing & parsing vocabulary

TermMeaning
CFG grammar (BNF/EBNF)Productions expr ::= expr '+' term | term; terminals = tokens, nonterminals = rules
AmbiguityOne string has two parse trees (dangling else, 1-2-3 without associativity). Fix it by layering the grammar or declaring precedence
LL(k) / recursive descentTop-down parser, one function per nonterminal, decides with k tokens of lookahead. Left recursion must be removed (A ::= A a loops forever)
LR / LALR(1)Bottom-up shift/reduce parser (yacc, bison). Handles left recursion. Conflicts show up as shift/reduce or reduce/reduce
Precedence climbing / PrattRecursive descent for expressions: parse_expr(min_prec) loops while the next operator's precedence ≥ min_prec. Left-assoc operators recurse with prec+1
PEG / packratOrdered choice /, never ambiguous, memoized. CPython's parser has been PEG-based since 3.9
ANTLR 4ALL(*) parser generator: antlr4 Expr.g4 -Dlanguage=Python3, generates Listener/Visitor classes, tolerates direct left recursion
Lark (Python)Lark(grammar, parser="lalr") or "earley" (the default). Transformer turns the tree into values
Concrete vs abstract syntax treeA CST keeps every token (needed for formatters and round-tripping). An AST keeps the structure that matters for meaning

Part 2 — Lowering to Intermediate Representations

TAC, basic blocks, CFG, dominators, SSA

ConceptRule / definition
Three-address codeAt most one operator per instruction: t1 = b * c; t2 = a + t1. Control flow becomes if x goto L / goto L
Leaders(1) the first instruction, (2) any jump target, (3) the instruction right after a jump. A basic block runs from one leader up to the next
Basic blockSingle entry, single exit, straight-line code. If its first instruction runs, all of them run
CFGNodes are blocks. Edges are jumps and fall-throughs. Add unique ENTRY and EXIT nodes
Short-circuit loweringa and b becomes branches, not an AND instruction, because b must not be evaluated when a is false
Dominanced dom n if every ENTRY→n path passes through d. Dom(n) = {n} ∪ ∩p∈pred(n) Dom(p). The immediate dominators form the dominator tree
Back edge / natural loopEdge n→h where h dom n. The loop body is h plus everything that reaches n without passing through h
Dominance frontierDF(d) = nodes where d's dominance ends: d dominates a predecessor but does not strictly dominate the node. Place φ nodes there
SSAEach variable is assigned exactly once. At join points, x3 = φ(x1, x2) selects by incoming edge
Construction (Cytron et al.)(1) dominator tree + DF, (2) insert φ on the iterated DF of each variable's def blocks (pruned SSA: only where the variable is live), (3) rename vars in a dominator-tree DFS
Why SSA helpsDef-use chains become explicit (one def per name). Sparse analyses (SCCP, GVN) and register allocation get easier
Out of SSAReplace φ with copies on predecessor edges. Split critical edges first (lost-copy / swap problems)

Part 3 — Static Analysis Theory

Dataflow analysis: the four classics

AnalysisDirectionMay/must (meet)GEN[B]KILL[B]Used for
Reaching definitionsForwardMay (∪)defs in B that survive to its endother defs of the same variablesuse-def chains, uninitialized vars, constant prop
Live variablesBackwardMay (∪)vars used before being defined in Bvars defined in Bdead stores, register allocation
Available expressionsForwardMust (∩)exprs computed in B, operands not redefined afterexprs whose operands B redefinescommon subexpression elimination
Very busy expressionsBackwardMust (∩)exprs evaluated in B before any operand is redefinedexprs whose operands B definescode hoisting
ConceptRule
Forward equationsIN[B] = ⊓p∈pred(B) OUT[p]; OUT[B] = GEN[B] ∪ (IN[B] − KILL[B])
Backward equationsOUT[B] = ⊓s∈succ(B) IN[s]; IN[B] = GEN[B] ∪ (OUT[B] − KILL[B])
InitializationMay analyses start at ∅. Must analyses start at the universal set (except the boundary node)
Worklist algorithmSeed every node. Pop a node, recompute it, and if OUT changed push its successors (predecessors when going backward). Process in reverse postorder (forward) or postorder (backward) for speed
TerminationTransfer functions are monotone and the lattice has finite height, so the solution only climbs and must stop. Cost is O(height × edges) node visits
MOP vs MFPMOP meets over every path (the ideal, not computable in general). MFP is the iterative fixpoint. MFP ⊑ MOP in general, and they are equal when transfer functions are distributive (all gen/kill analyses). Constant propagation is not distributive, so there MFP is strictly less precise
Constant propagation lattice⊤ (undefined) > constants c > ⊥ (not-a-constant). The flat lattice has height 2. Meet of two different constants is ⊥ (NAC)

Lattices & abstract interpretation

TermMeaning
Complete latticeA partial order where every subset has a join ⊔ (least upper bound) and a meet ⊓, with ⊥ and ⊤
Monotone functionx ⊑ y ⇒ f(x) ⊑ f(y). Tarski: the least fixpoint exists. Kleene: reach it by iterating from ⊥
Galois connection (α, γ)α(concrete set) ⊑ a ⇔ set ⊆ γ(a). α abstracts and γ concretizes
SoundnessThe abstract result over-approximates every concrete execution: collecting semantics ⊆ γ(abstract result)
Sign domain{⊥, −, 0, +, ⊤}. Finite, so iteration stops without widening. + × − = −, + + − = ⊤
Interval domain[l, h] with l, h ∈ ℤ ∪ {±∞}. It has infinite height, so loops need widening
Widening ∇[a,b] ∇ [c,d] = [c<a ? −∞ : a, d>b ? +∞ : b]. Forces termination and over-approximates
Narrowing ΔRuns after widening and refines only the infinite bounds: i=0; while i<100: i+=1 widens to [0,+∞] and narrows to [0,100]
Relational domainsOctagons (±x ±y ≤ c) and polyhedra track relations such as i < n. More precise, more expensive (Astrée, Apron)

Interview one-liners

QuestionCrisp answer
Sound vs complete?Sound: no false negatives (every real bug is reported, so it over-approximates). Complete: no false positives (every report is real, so it under-approximates). Some put it the other way round for "proving correctness", so state your convention
Rice's theoremEvery non-trivial semantic property of programs is undecidable. So any analysis that always terminates must give up soundness or completeness (or both)
Precision / recallPrecision = TP/(TP+FP), which developers feel as trust. Recall = TP/(TP+FN), which is coverage of real bugs. Industrial tools favor precision (if they don't trust it, they won't use it)
SoundySound except for documented features such as reflection, dynamic loading, native code and eval. Most "sound" Java and Python tools are soundy
Why is dataflow guaranteed to terminate?Monotone transfer functions on a finite-height lattice. Without finite height (intervals), use widening
MFP vs MOP?Equal for distributive frameworks. MFP is safe but less precise for non-distributive ones such as constant propagation
Andersen vs Steensgaard?Subset vs unification: cubic and precise vs near-linear and coarse. Andersen is the usual choice when you can pay for it
AST vs IR for analysis?The AST is right for syntactic linting and refactoring that must preserve the source. A CFG/SSA IR is right for semantic flow questions, because control flow and defs/uses are explicit
Why do Error Prone and Infer run at scale?They are compositional and incremental (per-file or per-procedure summaries), integrated into code review, and tuned for very low false-positive rates
