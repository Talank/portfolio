# १५ — आफ्नै प्रकाशस्तम्भ: सानो analyzer बनाउने र interview को तयारी

पन्ध्रौं टापुमा कुनै मान्छे बस्दैन। यहाँ एउटा खाली चट्टान मात्र छ, र चट्टानको टुप्पोमा कसैले प्रकाशस्तम्भ बनाउन सुरु गरेर छोडेको छ।

लुफीले टोलीतिर फर्केर भन्यो — [luffy:excited]"यो हामी आफैं बनाउँछौं! अहिलेसम्म हामीले अरूका औजार हेर्‍यौं। अब हाम्रो आफ्नै बत्ती बल्छ।"[/]

फ्राङ्कीले औजारको बाकस खोल्यो। नामीले नक्सा फैलाइन्। रोबिनले पहिलेका टापुका सबै तरिका एक एक गरी सम्झाइन्।

हाम्रो प्रकाशस्तम्भ एउटा सानो Python analyzer हो। यसले Python file पढ्छ, हरेक function को CFG बनाउँछ, liveness चलाउँछ, र मान राखिएको तर कहिल्यै नपढिएको variable को report दिन्छ। यस्तो गल्तीलाई dead store भनिन्छ।

@read teach
पहिलो तह जग हो, र जग parse हो। हरेक file ast dot parse ले पढिन्छ। file मा syntax error छ भने analyzer रोकिँदैन, त्यो file को error report गर्छ र अर्को file मा जान्छ।

दोस्रो तह भित्ता हो, र भित्ता CFG हो। हरेक FunctionDef का लागि statement क्रमैसँग हेरिन्छन्। सिधा statement अहिलेको block मा थपिन्छ। if आयो भने शर्तको block बाट then र else तिर edge जान्छ, र दुवै पछि नयाँ join block मा मिल्छन्। while वा for आयो भने header block बन्छ, body बाट header मा पछाडि फर्कने edge हुन्छ, र header बाट loop पछिको block मा अर्को edge हुन्छ। return ले exit तिर edge बनाउँछ।

तेस्रो तह सिँढी हो, र सिँढी use र def हो। हरेक block भित्र Name node हेरिन्छ। Name को ctx Store छ भने त्यो def हो। Load छ भने त्यो use हो। block भित्र def हुनुअघि नै use भएको variable मात्र block को use समूहमा जान्छ।

चौथो तह बत्ती हो, र बत्ती worklist हो। नवौं टापुको liveness यहीँ चल्छ। अनि पाँचौं तह ऐना हो, र त्यसले report लाई मान्छेसम्म पुर्‍याउँछ।

अब पूरा प्रकाशस्तम्भ बनाउने तरिका एकैचोटि सुन।

@algo mini-analyzer
सानो analyzer यसरी बनाऊ। पहिलो, हरेक file ast dot parse ले पढ, र syntax error आए त्यो file को error report गरेर अगाडि बढ। दोस्रो, हरेक function को CFG बनाऊ। सिधा statement अहिलेको block मा थप। if मा then र else का block बनाएर दुवैलाई join block मा जोड। loop मा header block बनाऊ, body बाट header मा back edge राख, र header बाट exit edge राख। return लाई exit node सँग जोड। तेस्रो, हरेक block मा Name node घुम, Store लाई def र Load लाई use मान, र block को use र def समूह बनाऊ। चौथो, liveness को backward worklist चलाऊ, जहाँ OUT भनेको successor का IN को union हो, र IN भनेको use union OUT माइनस def हो। पाँचौं, हरेक assignment लाई block भित्र पछाडिबाट जाँच, र assignment पछि त्यो variable live छैन भने dead store को चेतावनी बनाऊ। छैटौं, हरेक चेतावनीमा file, line, column, नियमको नाम, र छोटो सन्देश राख, अनि text, JSON, वा SARIF मा लेख। सातौं, साना test file बनाऊ, जसमा अपेक्षित चेतावनी पहिल्यै लेखिएको होस्, र analyzer को नतिजा त्यससँग मिलाऊ।
@end

फ्राङ्कीले अन्तिम ढुङ्गा राख्यो। [franky]"जग, भित्ता, सिँढी, बत्ती, र ऐना,"[/] उसले भन्यो। [franky]"पाँचै तह हाम्रो यात्राका टापुबाट आए।"[/]

यो साँचो हो। parse तेस्रो टापुबाट आयो। CFG छैटौं टापुबाट आयो। worklist नवौं टापुबाट आयो। report को ढाँचा तेह्रौं र चौधौं टापुका पहरेदारबाट आयो।

एउटा उदाहरण मनमा चलाऊ। function भित्र x बराबर एक लेखिएको छ। अनि x बराबर दुई लेखिएको छ। अनि x फिर्ता दिइएको छ। पहिलो assignment पछि x live छैन, किनभने अर्को statement ले x पढ्नुअघि नै नयाँ मान राख्छ। त्यसैले analyzer ले पहिलो लाइनमा dead store भन्छ।

तर ध्यान देऊ। for loop को underscore वा जानीजानी राखिएको मानमा चेतावनी दिनु हुँदैन। global र nonlocal variable अर्को function ले पढ्न सक्छ, त्यसैले तिनमा पनि चेतावनी दिनु हुँदैन। यस्ता नियमले false positive घटाउँछन्।

@recall mini-analyzer | प्रकाशस्तम्भको बत्ती पहिलो पटक बल्यो, र हामी त्यो बनाउने तरिका फेरि सुन्छौं।

@read hush
बत्तीको उज्यालो समुद्रमा बिस्तारै घुम्छ। एक पटक यता आउँछ, अनि टाढा जान्छ, अनि फेरि आउँछ।

अब interview को तयारी सुन। कम्पाइलर र program analysis को interview मा प्रायः तीन किसिमका प्रश्न आउँछन्। पहिलो किसिम परिभाषा हो, जस्तै SSA के हो, वा basic block के हो। दोस्रो किसिम तरिका हो, जस्तै worklist algorithm भन, वा phi कहाँ राख्ने भन। तेस्रो किसिम design हो, र त्यहाँ यो codebase मा यो bug कसरी खोज्ने भनेर सोधिन्छ।

design को प्रश्नमा उत्तर यसरी बनाऊ। सुरुमा प्रस्तावनाका तीन प्रश्न सोध। कोड कुन रूपमा हेर्ने, कुन तथ्य खोज्ने, र उत्तर कति sound चाहिन्छ। अनि सस्तो औजारबाट सुरु गर, र आवश्यक भए मात्र महँगो analysis थप। अन्त्यमा false positive र false negative को सम्झौता खुलेर भन।

@recall mini-analyzer | प्रकाशस्तम्भ छोड्नुअघि यो तरिका अन्तिम पटक सुन।

@read hush
टोली चट्टानमा बस्यो, र बत्ती घुमेको हेर्‍यो। कसैले केही भनेन। बत्तीले आफ्नो काम गरिरह्यो।

@tier medium

अब यो analyzer लाई अलि बलियो बनाउने बाटा सुन। पहिलो बाटो reaching definitions थप्नु हो। त्यसले variable मा मान नराखी पढिएको ठाउँ भेटाउँछ। Python मा यस्तो ठाउँमा UnboundLocalError आउँछ, र त्यो analyzer ले चलाउनुअघि नै भन्न सक्छ।

दोस्रो बाटो सानो taint analysis थप्नु हो। input बाट आएको मान tainted बनाऊ, assignment मा बगाऊ, र eval वा os dot system मा पुग्यो भने report गर। यो एउटै function भित्र गर्दा पनि धेरै उपयोगी हुन्छ।

तेस्रो बाटो SARIF मा report लेख्नु हो। SARIF भनेको static analysis को नतिजा लेख्ने JSON को मानक हो। GitHub को code scanning ले SARIF पढ्छ, र pull request मै चेतावनी देखाउँछ। त्यसैले तिम्रो सानो analyzer पनि ठूला औजार जस्तै देखिन्छ।

चौथो बाटो नाप लिनु हो। चिनिएका bug भएका file राख, र analyzer ले कति साँचो bug भेट्यो, कति छुटायो, र कति झूटो घण्टी बजायो भनेर गन। यसलाई precision र recall भनिन्छ। research मा यही नापले औजारको मूल्य बताउँछ।

@tier long

रोबिनले बत्तीको छेउमा बसेर interview का केही छोटा उत्तर सुनाइन्, र तिमी ती उत्तर सपनामा पनि बोल्न सक्छौ।

AST र CFG मा फरक के हो? AST ले code को व्याकरणीय आकार देखाउँछ। CFG ले code चल्ने सम्भावित बाटो देखाउँछ। AST मा if एउटा node हो। CFG मा if दुई बाटोमा फाट्ने ठाउँ हो।

sound र complete मा फरक के हो? sound analysis ले कुनै साँचो bug छुटाउँदैन, तर झूटो चेतावनी दिन सक्छ। complete analysis ले झूटो चेतावनी दिँदैन, तर साँचो bug छुटाउन सक्छ। Rice को theorem का कारण रोचक property मा दुवै एकैचोटि पाइँदैन।

Andersen र Steensgaard मा फरक के हो? Andersen ले subset constraint प्रयोग गर्छ, र यो ठीक तर ढिलो छ। Steensgaard ले unification प्रयोग गर्छ, र यो छिटो तर धमिलो छ।

SSA किन चाहिन्छ? हरेक नामको एउटै परिभाषा हुने भएकाले def use chain सजिलै बन्छ, र धेरै optimization र analysis छिटो र सरल हुन्छन्।

यी उत्तर छोटा छन्। तर हरेक उत्तरको पछाडि एउटा टापु छ, र हरेक टापुमा एउटा तरिका छ जुन तिमीले तीन पटक सुन्यौ।

@read hush
प्रकाशस्तम्भको बत्ती घुमिरहन्छ। त्यसको उज्यालो कहिलेकाहीँ तिम्रो परेलामा पर्छ, र फेरि अँध्यारोमा जान्छ। तिमी त्यही लयमा सास फेर्दै छौ।
