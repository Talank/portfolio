# २ — शब्द र वाक्यको घाट: lexing, parsing र precedence

दोस्रो टापुमा एउटा पुरानो घाट छ। घाटमा काठका लामा पेटी छन्, र पेटीमा अक्षर कुँदिएका ढुङ्गा एक लाइनमा राखिएका छन्।

उसप्प ढुङ्गाको लाइनमा हिँड्न थाल्यो। [usopp]"यहाँ त अक्षर मात्र रहेछन्,"[/] उसले भन्यो। [usopp]"कहाँ शब्द सुरु हुन्छ, कहाँ सकिन्छ, केही थाहा हुँदैन।"[/]

यही नै lexer को काम हो। lexer ले अक्षरको लाइन बायाँबाट दायाँ पढ्छ, र हरेक पटक सकेसम्म लामो शब्द काट्छ। यस नियमलाई maximal munch भनिन्छ।

maximal munch किन चाहिन्छ? मानौं कोडमा दुई वटा बराबरको चिन्ह छन्। lexer ले ती दुईलाई दुई वटा token बनाउँदैन, एउटै तुलना गर्ने token बनाउँछ, किनभने लामो मिल्ने टुक्रा जित्छ। त्यसैगरी iffy भन्ने नाम if भन्ने keyword होइन, किनभने पूरा शब्द लामो छ।

हरेक token को एउटा kind हुन्छ, र एउटा text हुन्छ। number, identifier, keyword, operator, र कोष्ठक token का kind हुन्। राम्रो lexer ले हरेक token सँग line र column पनि राख्छ, ताकि पछि error आउँदा ठाउँ देखाउन सकियोस्।

अब नामी अगाडि आइन्। उनको हातमा एउटा सानो तराजु छ।

[nami]"शब्द त छुट्टिए,"[/] उनले भनिन्। [nami]"तर वाक्यको आकार अझै बनेको छैन। a प्लस b गुणा c मा पहिले कुन जोडिन्छ, त्यो तराजुले भन्छ।"[/]

@read teach
यहाँ grammar आउँछ। grammar भनेको नियमको सूची हो, र हरेक नियमलाई production भनिन्छ। जस्तै, expression भनेको term प्लस term हो, र term भनेको factor गुणा factor हो। expression र term जस्ता नामलाई nonterminal भनिन्छ, र token लाई terminal भनिन्छ।

यो grammar बाट parser बनाउने सबैभन्दा सरल तरिकालाई recursive descent भनिन्छ। हरेक nonterminal का लागि एउटा function लेखिन्छ। expression को function ले term को function बोलाउँछ, र term को function ले factor को function बोलाउँछ।

तर यहाँ एउटा पासो छ। यदि नियम यस्तो छ कि expression भनेको expression प्लस term हो, भने function ले सुरुमै आफैंलाई बोलाउँछ, र कहिल्यै रोकिँदैन। यसलाई left recursion भनिन्छ। recursive descent मा यसलाई loop मा बदलिन्छ।

धेरै तह भएका operator का लागि हरेक तहको छुट्टै function लेख्दा कोड लामो हुन्छ। त्यसैले एउटा चलाख तरिका छ, र त्यसलाई precedence climbing भनिन्छ। हरेक operator को एउटा तौल हुन्छ। प्लस र माइनसको तौल एक हुन्छ, गुणा र भागको तौल दुई हुन्छ।

अब नामीको तराजु सुन। यो आजको तरिका हो।

@algo precedence-climbing
precedence climbing को तरिका यस्तो छ। parse expression नामको function ले एउटा न्यूनतम तौल लिन्छ, र सुरुमा त्यो तौल शून्य हुन्छ। पहिलो, parse primary बोलाएर बायाँको टुक्रा पढ। primary भनेको number वा identifier हो, वा कोष्ठक भित्रको पूरै expression हो, जसलाई फेरि शून्य तौलबाट parse गरिन्छ र पछि बन्द कोष्ठक माग्छ। दोस्रो, अर्को token कुनै binary operator हो र त्यसको तौल न्यूनतम तौलभन्दा कम छैन भने, त्यो operator खाऊ। तेस्रो, दायाँको टुक्राका लागि नयाँ न्यूनतम तौल निकाल। operator left associative छ भने त्यो तौल operator को तौल प्लस एक हुन्छ, र right associative छ भने operator कै तौल हुन्छ। चौथो, त्यही नयाँ तौल दिएर parse expression फेरि बोलाऊ, र दायाँको टुक्रा पाऊ। पाँचौं, बायाँ, operator, र दायाँ मिलाएर नयाँ binary node बनाऊ, र त्यसलाई नै नयाँ बायाँ मान। अर्को operator को तौल कम हुँदासम्म दोस्रो कदमदेखि दोहोर्‍याऊ, अनि बायाँको टुक्रा फिर्ता देऊ।
@end

उसप्पले कागजमा उदाहरण चलाएर हेर्‍यो। a पढियो। प्लस आयो, र त्यसको तौल एक हो। अब दायाँका लागि न्यूनतम तौल दुई भयो। दायाँमा b पढियो। गुणा आयो, र त्यसको तौल दुई हो, जुन न्यूनतम तौलभन्दा कम छैन। त्यसैले b र c गुणामा जोडिए। अनि मात्र a सँग प्लस जोडियो।

[usopp]"वाह, गुणा आफैं तल झर्‍यो!"[/] उसले भन्यो।

[nami]"गह्रौं operator नजिक टाँसिन्छ,"[/] नामीले भनिन्। [nami]"हल्का operator माथि बस्छ। रुखमा जति तल, उति पहिले हिसाब हुन्छ।"[/]

अब associativity को कुरा सुन। a माइनस b माइनस c मा पहिले a बाट b घटाइन्छ। त्यसैले माइनस left associative हो, र दायाँलाई तौल प्लस एक दिइन्छ, ताकि अर्को माइनसले दायाँ टुक्रा खान नपाओस्। तर घात, अर्थात power, right associative हुन्छ। दुईको तीनको दुई भन्दा पहिले तीनको दुई हिसाब हुन्छ।

@recall precedence-climbing | अब तराजु फेरि उठाऔं, र उही तरिका बिस्तारै सुनौं।

@read hush
घाटमा छाल आउँछ र जान्छ। अक्षर कुँदिएका ढुङ्गा चन्द्रमाको उज्यालोमा हल्का चम्किन्छन्।

अब parser generator को कुरा गरौं। हातैले parser लेख्नु पर्दैन, किनभने grammar लेखिदिए औजारले parser बनाइदिन्छ। ANTLR यस्तै औजार हो। yacc र bison पनि यस्तै पुराना औजार हुन्।

ती औजार दुई परिवारका हुन्छन्। एउटा परिवार माथिबाट तल जान्छ, र त्यसलाई LL parsing भनिन्छ। recursive descent र ANTLR यही परिवारका हुन्। अर्को परिवार तलबाट माथि जान्छ, र त्यसलाई LR parsing भनिन्छ। yacc र bison यही परिवारका हुन्।

LR parser ले stack प्रयोग गर्छ। त्यसले token एक एक गरी stack मा धकेल्छ, र त्यसलाई shift भनिन्छ। stack को माथि कुनै नियमको दायाँ भाग पूरा देखियो भने, त्यसलाई नियमको बायाँ नाममा खुम्च्याउँछ, र त्यसलाई reduce भनिन्छ।

तर आज पनि GCC, Clang, र धेरै ठूला compiler ले हातैले लेखेको recursive descent प्रयोग गर्छन्। किनभने त्यसमा error message राम्रो बनाउन सजिलो हुन्छ, र कोड पढ्न पनि सजिलो हुन्छ।

@recall precedence-climbing | घाट छोड्नुअघि नामीको तराजु अन्तिम पटक सुन।

@read hush
नामीले तराजु झोलामा राखिन्। उसप्पले अन्तिम ढुङ्गा छोयो, र हामी जहाजतिर फर्कियौं।

@tier medium

अब ambiguity को कुरा सुन, र यो interview मा प्रायः सोधिन्छ।

कुनै grammar ले एउटै token को लाइनबाट दुई वटा फरक रुख बनाउन दिन्छ भने, त्यो grammar ambiguous हुन्छ। सबैभन्दा प्रसिद्ध उदाहरण dangling else हो।

if भित्र अर्को if छ, र अन्त्यमा एउटा else छ भने, त्यो else कुन if को हो? बाहिरको if को पनि हुन सक्छ, भित्रको if को पनि हुन सक्छ। धेरै भाषाले नियम बनाएका छन् कि else सधैं सबैभन्दा नजिकको if को हुन्छ।

अर्को शब्द lookahead हो। parser ले निर्णय गर्न अगाडिका कति token हेर्छ भन्ने कुरालाई lookahead भनिन्छ। LL एक parser ले एउटा मात्र token हेरेर कुन नियम लगाउने भनेर छान्छ।

parser ले error भेट्दा के गर्छ भन्ने कुरा पनि महत्त्वपूर्ण छ। राम्रो parser पहिलो error मै रोकिँदैन। त्यसले अर्धविराम वा बन्द कोष्ठक जस्ता सुरक्षित token नआउँदासम्म token फ्याँक्छ, अनि फेरि parse गर्न थाल्छ। यसलाई panic mode recovery भनिन्छ।

@tier long

जोरो घाटको छेउमा बसेर तरबार पुछिरहेको थियो। [zoro]"मलाई एउटा कुरा भन,"[/] उसले भन्यो। [zoro]"lexer ले regular expression प्रयोग गर्छ भने parser ले किन गर्दैन?"[/]

रोबिनले जवाफ दिइन्। [robin]"regular expression ले गन्न जान्दैन,"[/] उनले भनिन्। [robin]"कति वटा कोष्ठक खुले, र कति बन्द हुनुपर्छ भन्ने कुरा सम्झन stack चाहिन्छ। grammar र parser सँग त्यो stack हुन्छ, चाहे त्यो function call को stack होस् वा LR को आफ्नै stack होस्।"[/]

यो कुरा Chomsky को तहसँग जोडिन्छ। regular language सबैभन्दा सरल तह हो, र त्यसलाई finite automaton ले चिन्छ। context free language त्यसभन्दा माथिको तह हो, र त्यसलाई stack भएको automaton ले चिन्छ। धेरैजसो programming language को आकार context free grammar ले लेखिन्छ।

तर पूरा भाषा context free हुँदैन। variable प्रयोग गर्नुअघि घोषणा हुनुपर्छ भन्ने नियम grammar ले जाँच्न सक्दैन। त्यो काम semantic analysis को कोठामा हुन्छ, र यसैले pipeline मा त्यो छुट्टै कोठा छ।

अन्तिममा एउटा व्यावहारिक कुरा सुन। Python को आफ्नै parser अहिले PEG parser हो। PEG मा विकल्पहरू क्रमैसँग प्रयास गरिन्छ, र पहिलो मिल्ने विकल्प जित्छ, त्यसैले त्यहाँ ambiguity हुँदैन।
