# ७ — एकै नामको टापु: SSA, dominator र phi

सातौं टापु सानो छ। यहाँका मान्छेको एउटा अनौठो नियम छ। कसैले पनि आफ्नो नाम दुई पटक प्रयोग गर्दैन। हरेक पटक कुनै मान्छेले नयाँ काम सुरु गर्छ, उसले नयाँ नामको पट्टी लगाउँछ।

उसप्पले गाउँको ढोकामा रोकिएर पढ्यो। [usopp]"x एक, x दुई, x तीन,"[/] उसले भन्यो। [usopp]"यहाँ त एउटै मान्छेका तीन नाम रहेछन्।"[/]

[robin]"एउटै मान्छे होइन,"[/] रोबिनले भनिन्। [robin]"एउटै variable का तीन वटा मान हुन्। र हरेक मानको आफ्नै नाम छ।"[/]

@read teach
यही SSA हो। SSA को पूरा नाम static single assignment हो। यसको नियम यस्तो छ कि हरेक variable मा program भरि एक पटक मात्र मान राखिन्छ। x मा दोस्रो पटक मान राख्नुपर्‍यो भने त्यो नयाँ नाम बन्छ, जस्तै x दुई।

यसको फाइदा के हो? SSA मा हरेक नामको एउटा मात्र जन्मस्थान हुन्छ। त्यसैले x दुई कहाँ प्रयोग भयो भनेर सोध्दा, त्यसको मान कहाँबाट आयो भनेर खोजिरहनु पर्दैन। जवाफ एउटै ठाउँमा हुन्छ। यसले constant propagation र dead code elimination जस्ता धेरै analysis सजिलो र छिटो बनाउँछ।

तर समस्या दोबाटोमा आउँछ। if को एउटा हाँगामा x एक बन्छ, र अर्को हाँगामा x दुई बन्छ। दुवै हाँगा मिल्ने ठाउँमा x को कुन नाम प्रयोग हुन्छ?

त्यसका लागि phi function छ। दुवै हाँगा मिल्ने block को सुरुमा x तीन बराबर phi x एक, x दुई लेखिन्छ। यसको अर्थ के हो भने, पहिलो हाँगाबाट आइयो भने x तीन मा x एक आउँछ, र दोस्रो हाँगाबाट आइयो भने x दुई आउँछ।

नामीले गाउँको चोकमा एउटा सानो ढुङ्गाको मन्दिर देखाइन्। [nami]"यही phi हो,"[/] उनले भनिन्। [nami]"यो मन्दिरले तिमी कुन बाटोबाट आयौ भनेर सम्झिन्छ, र त्यसै अनुसार नाम दिन्छ।"[/]

अब phi कहाँ राख्ने भन्ने प्रश्न आउँछ। हरेक join point मा हरेक variable को phi राख्यो भने धेरै फोहोर हुन्छ। त्यसैले dominance frontier भन्ने कुरा प्रयोग गरिन्छ।

पहिले dominance सम्झ। entry बाट B सम्मको हरेक बाटोमा A आउँछ भने, A ले B लाई dominate गर्छ। अब block X को dominance frontier भनेको यस्ता block को समूह हो, जहाँ X को शासन ठीक सकिन्छ। अर्थात्, X ले त्यो block को कुनै predecessor लाई dominate गर्छ, तर त्यो block आफैंलाई strictly dominate गर्दैन।

त्यो ठाउँ किन महत्त्वपूर्ण छ? किनभने X मा राखिएको मान त्यहाँ पहिलो पटक अर्को बाटोबाट आएको मानसँग भेट्छ। त्यसैले phi ठीक त्यहीँ चाहिन्छ। अब यो टापुको तरिका सुन।

@algo phi-placement
SSA बनाउने तरिका यस्तो छ। पहिलो, CFG बनाऊ, हरेक block को immediate dominator निकाल, र dominator tree बनाऊ। दोस्रो, हरेक block को dominance frontier निकाल, जुन ती block हुन् जसको कुनै predecessor लाई यो block ले dominate गर्छ तर जसलाई आफैंलाई strictly dominate गर्दैन। तेस्रो, हरेक variable v का लागि v मा मान राख्ने सबै block लाई worklist मा राख। worklist बाट एउटा block X झिक। X को dominance frontier को हरेक block Y मा v को phi अझै छैन भने, त्यहाँ v बराबर phi राख, र त्यसमा Y को हरेक predecessor का लागि एउटा argument राख। त्यो phi आफैं v को नयाँ परिभाषा भएकाले, Y लाई पनि worklist मा थप। worklist खाली नहुँदासम्म दोहोर्‍याऊ। चौथो, नाम फेर्न dominator tree माथिबाट तल घुम, र हरेक variable को एउटा stack राख। हरेक block मा प्रयोग भएको नामलाई stack को माथिल्लो नामले बदल, नयाँ परिभाषामा नयाँ नाम बनाएर stack मा धकेल, successor का phi मा यो बाटोको argument भर, child घुम, र फर्कंदा आफूले धकेलेका नाम झिक।
@end

उसप्पले मन्दिरको वरिपरि घुमेर हेर्‍यो। [usopp]"त्यो तेस्रो कदममा worklist फेरि आयो,"[/] उसले भन्यो। [usopp]"phi राख्दा नयाँ नाम जन्मियो, त्यसैले त्यसको frontier मा पनि अर्को phi चाहिन सक्छ।"[/]

[robin]"ठीक भन्यौ,"[/] रोबिनले भनिन्। [robin]"loop मा यो प्रायः हुन्छ। loop header मा phi आउँछ, किनभने त्यहाँ loop भन्दा अघिको मान र पछाडि फर्केको मान भेट्छन्।"[/]

एउटा उदाहरण मनमा हेर। i सुरुमा शून्य हुन्छ, र loop मा i मा एक थपिन्छ। SSA मा i एक बराबर शून्य हुन्छ। loop header मा i दुई बराबर phi i एक, i तीन हुन्छ। loop भित्र i तीन बराबर i दुई प्लस एक हुन्छ। पहिलो पटक header मा i एक आउँछ, र त्यसपछि हरेक पटक पछाडि फर्केको i तीन आउँछ।

गाउँका मान्छे निदाइसकेका छन्। ढोकामा झुण्डिएका नामका पट्टी हावामा हल्का हल्लिन्छन्।

अब LLVM IR को कुरा सुन। LLVM IR आफैं SSA मा हुन्छ। त्यहाँ प्रतिशतको चिन्हबाट सुरु हुने नाम हुन्छन्, र ती virtual register हुन्। हरेक virtual register मा एक पटक मात्र मान राखिन्छ, र join point मा phi instruction लेखिन्छ।

तर Clang ले सुरुमा सबै local variable लाई memory मा राख्छ, र त्यसका लागि alloca, load, र store प्रयोग गर्छ। त्यसपछि mem2reg नामको pass ले ती memory का variable लाई register मा बदल्छ, र आवश्यक ठाउँमा phi राख्छ। त्यो pass ले ठीक आजकै तरिका प्रयोग गर्छ।

उसप्पले आफ्नो छातीमा उसप्प एक भनेर लेखिएको नक्कली पट्टी टाँस्यो, अनि मुस्कुरायो। हामी जहाजतिर फर्कियौं।

@tier medium

dominator निकाल्ने तरिका पनि छोटकरीमा सुन। सुरुमा entry को dominator entry आफैं मात्र हो भनिन्छ, र अरू सबै block को dominator सबै block हुन् भनिन्छ। अनि हरेक block का लागि उसका सबै predecessor का dominator को साझा भाग लिइन्छ, र त्यसमा block आफैं थपिन्छ। केही नफेरिउन्जेल यो दोहोर्‍याइन्छ।

यो पनि एउटा worklist वा iterative तरिका हो, र नवौं टापुमा हामी यही ढाँचा फेरि भेट्नेछौं। Cooper, Harvey, र Kennedy को सरल तरिका यही विचारमा छिटो चल्छ। Lengauer र Tarjan को तरिका अझ छिटो छ, तर लेख्न गाह्रो छ।

SSA बाट बाहिर निस्कने काम पनि हुन्छ, किनभने वास्तविक मेसिनमा phi हुँदैन। त्यसका लागि हरेक predecessor block को अन्त्यमा copy राखिन्छ। x तीन बराबर phi x एक, x दुई छ भने, पहिलो हाँगाको अन्त्यमा x तीन बराबर x एक राखिन्छ, र दोस्रो हाँगाको अन्त्यमा x तीन बराबर x दुई राखिन्छ।

@tier long

चपरले सोध्यो — [chopper]"सबै join point मा phi राख्दा के बिग्रन्छ?"[/]

बिग्रन्छ भन्दा पनि बेकार हुन्छ। त्यसलाई maximal SSA भनिन्छ, र त्यसमा धेरै phi हुन्छन् जुन कहिल्यै प्रयोग हुँदैनन्। dominance frontier ले minimal SSA दिन्छ, जहाँ phi आवश्यक ठाउँमा मात्र हुन्छ।

त्यसभन्दा पनि सफा रूपलाई pruned SSA भनिन्छ। त्यहाँ phi राख्नुअघि variable त्यो block मा live छ कि छैन भनेर जाँचिन्छ। live छैन भने, अर्थात् अगाडि कसैले त्यो मान पढ्दैन भने, phi नै राखिँदैन।

live भन्ने शब्द नवौं टापुमा धेरै आउँछ। अहिलेलाई यति सम्झ कि live variable भनेको यस्तो variable हो, जसको अहिलेको मान अगाडि कतै पढिनेछ।

SSA ले static analysis लाई पनि मद्दत गर्छ। हरेक नामको एउटै परिभाषा भएकाले, def use chain सजिलै बन्छ। कुनै नामबाट उसलाई प्रयोग गर्ने सबै instruction सिधै भेटिन्छन्। taint analysis र constant propagation दुवैले यो छोटो बाटो प्रयोग गर्छन्।
