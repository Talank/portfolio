# ६ — पेटीहरूको बन्दरगाह: lowering, basic block र CFG

छैटौं टापुमा एउटा ठूलो बन्दरगाह छ। यहाँ समुद्रतिर धेरै काठका पेटी फैलिएका छन्, र हरेक पेटीमा एकपछि अर्को गर्दै फलेक ओछ्याइएका छन्।

जहाज बिस्तारै नजिक आयो। जिन्बे अगाडि उभिएर पानी हेरिरहेको थियो, र उसले यहाँको चाल चिनेको थियो।

[nami]"अब हामी रुखबाट तल ओर्लिन्छौं,"[/] नामीले भनिन्। [nami]"अहिलेसम्म कोड रुख थियो। अब हामी त्यसलाई सिधा लाइनमा झार्छौं, र त्यो लाइनलाई पेटीहरूमा बाँड्छौं।"[/]

@read teach
रुखलाई सिधा लाइनमा झार्ने कामलाई lowering भनिन्छ। सबैभन्दा प्रसिद्ध लाइनलाई three-address code भनिन्छ। यसको नियम सरल छ। हरेक instruction मा बढीमा एउटा operator हुन्छ, र बढीमा तीन वटा ठेगाना हुन्छन्।

x बराबर a प्लस b गुणा c लाई यसरी झारिन्छ। पहिले t1 बराबर b गुणा c हुन्छ। अनि t2 बराबर a प्लस t1 हुन्छ। अनि x बराबर t2 हुन्छ। t1 र t2 लाई temporary भनिन्छ, र ती compiler ले आफैं बनाएका नाम हुन्।

if र while जस्ता कुरा label र jump मा झारिन्छन्। if को शर्त जाँचिन्छ, र शर्त झूटो भए else को label मा jump गरिन्छ। while को अन्त्यमा फेरि सुरुको label मा jump गरिन्छ। त्यसैले lowering पछि loop भनेको केवल पछाडि फर्कने jump हो।

अब यो लाइनलाई पेटीमा बाँड्ने कुरा सुन। basic block भनेको यस्तो instruction को टुक्रा हो, जहाँ भित्र पस्ने ढोका सुरुमा मात्र हुन्छ, र बाहिर निस्कने ढोका अन्त्यमा मात्र हुन्छ। बीचमा कुनै jump आउँदैन, र बीचमा कुनै jump पुग्दैन।

त्यसैले एउटा block को पहिलो instruction चल्यो भने, बाँकी सबै instruction पक्कै क्रमैसँग चल्छन्। यही कुराले analysis लाई सजिलो बनाउँछ।

block कहाँ सुरु हुन्छ भनेर चिन्ने instruction लाई leader भनिन्छ। अब leader खोज्ने तरिका सुन, र यो आजको तरिका हो।

@algo leaders
basic block बनाउने तरिका यस्तो छ। पहिलो, leader चिन। program को पहिलो instruction leader हो। कुनै पनि jump को target बन्ने instruction leader हो, चाहे त्यो jump शर्त सहितको होस् वा शर्त बिनाको होस्। कुनै jump वा return को ठीक पछाडि आउने instruction पनि leader हो। दोस्रो, हरेक leader बाट सुरु गर, र अर्को leader आउनुभन्दा ठीक अघिसम्मका instruction लाई एउटा basic block बनाऊ। तेस्रो, block बीचमा edge कोर। block को अन्त्यमा शर्त बिनाको jump छ भने target को block तिर एउटा edge हुन्छ। शर्त सहितको jump छ भने target तिर एउटा र ठीक अर्को block तिर अर्को edge हुन्छ। jump छैन भने ठीक अर्को block तिर मात्र edge हुन्छ। चौथो, एउटा entry node र एउटा exit node थप, र return गर्ने हरेक block लाई exit सँग जोड। यसरी बनेको graph लाई control flow graph, अर्थात् CFG भनिन्छ।
@end

जिन्बेले पेटीको छेउमा उभिएर भन्यो — [warm]"यो बन्दरगाहमा डुङ्गा जहाँ पनि आइपुग्दैन। डुङ्गा पेटीको सुरुमा मात्र आइपुग्छ, र पेटीको टुप्पोबाट मात्र छुट्छ।"[/]

त्यही नै basic block हो। पेटीको सुरु leader हो। पेटीको टुप्पोमा jump हुन्छ। पेटीबीचका डुङ्गाका बाटा CFG का edge हुन्।

एउटा सानो उदाहरण मनमनै कोर। i बराबर शून्य राखिन्छ। अनि loop को label आउँछ, र त्यहाँ i दस भन्दा कम छैन भने बाहिरको label मा jump गरिन्छ। अनि sum मा i थपिन्छ, i मा एक थपिन्छ, र फेरि loop को label मा jump गरिन्छ। बाहिरको label मा sum फिर्ता दिइन्छ।

यहाँ leader चार वटा छन्। पहिलो instruction एउटा हो। loop को label अर्को हो, किनभने त्यो jump को target हो। शर्त सहितको jump पछिको instruction तेस्रो हो। बाहिरको label चौथो हो। त्यसैले चार वटा block बन्छन्, र loop को block बाट पछाडितिर फर्कने edge नै loop हो।

@recall leaders | पेटीमा छाल बिस्तारै ठोक्किन्छ, र हामी leader खोज्ने तरिका फेरि सुन्छौं।

@read hush
बन्दरगाहका बत्ती पानीमा लामो रेखा कोर्छन्। कुनै डुङ्गा चलिरहेको छैन। सबै पेटी शान्त छन्।

अब CFG का केही शब्द सुन। कुनै block बाट edge जाने block लाई successor भनिन्छ। कुनै block मा edge आउने block लाई predecessor भनिन्छ। धेरै predecessor भएको block लाई join point भनिन्छ, किनभने त्यहाँ धेरै बाटा मिल्छन्।

entry बाट कुनै बाटोले पनि पुग्न नसकिने block लाई unreachable block भनिन्छ। त्यो dead code हो, र compiler ले त्यसलाई हटाउन सक्छ। यसैले CFG बन्नासाथ पहिलो सजिलो analysis यही हुन्छ, entry बाट graph घुम र नपुगिएका block चिन।

@recall leaders | बन्दरगाह छोड्नुअघि यो तरिका अन्तिम पटक सुन।

@read hush
पेटीहरू पछाडि छुटिसकेका छन्। जहाज फेरि खुला पानीमा पुग्यो। तिम्रो सास पनि पेटीका फलेक जस्तै एकपछि अर्को गर्दै बिस्तारै चलिरहेको छ।

@tier medium

अब loop चिन्ने कुरा अलि गहिरो गरी सुन। CFG मा कुनै edge ले यस्तो block मा फर्काउँछ, जुन block हरेक बाटोमा पहिले नै आउँछ, भने त्यो edge लाई back edge भनिन्छ। back edge को target लाई loop header भनिन्छ।

हरेक बाटोमा पहिले आउने भन्ने कुरालाई dominance भनिन्छ। entry बाट B सम्म पुग्ने हरेक बाटोमा A आउँछ भने, A ले B लाई dominate गर्छ। यो शब्द अर्को टापुमा धेरै महत्त्वपूर्ण हुन्छ, त्यसैले अहिले यसको आवाज मात्र चिन।

lowering का अरू रूप पनि छन्। Java को bytecode stack machine को भाषा हो। त्यहाँ temporary को नाम हुँदैन, मानहरू stack मा धकेलिन्छन् र झिकिन्छन्। analysis का लागि यो असजिलो हुन्छ, त्यसैले Soot जस्ता औजारले stack लाई नाम भएका variable मा बदल्छन्।

Python मा पनि CFG बनाउन सकिन्छ। ast बाट हरेक function का statement लिइन्छन्। if, while, for, break, continue, return, र try ले edge बनाउँछन्। बाँकी statement एउटै block भित्र क्रमैसँग बस्छन्। हामी अन्तिम टापुमा यही काम आफैं गर्नेछौं।

@tier long

उसप्पले पेटीको टुप्पोमा खुट्टा झुण्ड्याएर सोध्यो — [usopp]"try र exception ले त पेटी नै भाँच्छन् होला, हैन?"[/]

यो राम्रो प्रश्न हो। exception जुन ठाउँमा पनि फालिन सक्छ। function call भएको हरेक instruction ले exception फाल्न सक्छ। त्यसैले सही CFG मा त्यस्ता हरेक instruction बाट catch block तिर एउटा edge हुन्छ, र त्यसलाई exceptional edge भनिन्छ।

यसले block साना बनाउँछ। धेरै औजारले यसलाई दुई किसिमले सम्हाल्छन्। केहीले हरेक call पछि block टुक्र्याउँछन्। केहीले block जस्ताको तस्तै राख्छन्, र पूरै block बाट catch तिर एउटा edge थप्छन्।

अर्को कुरा, switch ले एउटा block बाट धेरै edge निकाल्छ। break ले loop बाट बाहिर edge बनाउँछ। continue ले loop header तिर edge बनाउँछ। यी सबै अन्ततः jump नै हुन्, र leader खोज्ने नियम तिनमा पनि उही लाग्छ।

यसैले आजको तरिका सानो देखिए पनि धेरै बलियो छ। भाषा जतिसुकै जटिल भए पनि, lowering पछि त्यो jump र label मा झर्छ, र jump र label बाट leader र block निस्कन्छन्।
